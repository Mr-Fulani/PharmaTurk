# Поиск товаров: EXPLAIN было/стало и SQL для проверки на проде (05.11.2026)

К PR #322. Устройство поиска — [PRODUCT_SEARCH.md](PRODUCT_SEARCH.md). Запрос как у подсказок в шапке:
`/api/catalog/products?search=…&page_size=6&view=card&include_facets=false`.

## Локально: модельный каталог

30 049 товаров, `external_data` ≈ 50 КБ на строку (таблица 1,5 ГБ), Postgres 15 в Docker,
`shared_buffers` 128 МБ. `EXPLAIN (ANALYZE, BUFFERS)` по SQL, который выполняет код: «было» — main
после #321 (3479b010), «стало» — эта ветка. Время — мс; буферы — hit + read верхнего узла.

| Запрос | COUNT было | COUNT стало | Страница было | Страница стало |
|---|---|---|---|---|
| «кр» | 4 872 мс / 706 881 | 42 мс / 15 902 | 5 048 мс / 706 882 | 77 мс / 15 914 |
| «ма» | 43 мс / 7 845 | 13 мс / 1 786 | 44 мс / 7 849 | 14 мс / 1 787 |
| «a» | 4 658 мс / 706 881 | 47 мс / 15 902 | 0,4 мс / 22 | 121 мс / 15 903 |
| «пленочной оболочкой» | 1 486 мс / 291 959 | 44 мс / 15 628 | 1 865 мс / 291 969 | 107 мс / 15 638 |
| «Abdi Ibrahim» | 77 мс / 18 986 | 2,2 мс / 1 827 | 102 мс / 20 130 | 6,0 мс / 2 971 |

У «a» страница «было» быстрая: однобуквенный запрос и в #321 шёл без сортировки по точности,
но его COUNT тот же — секунды.

Главное отличие планов: было `Seq Scan on catalog_product … Filter: … (NOT (external_data ?
'source_variant_id')) …` по всем строкам (детоаст дампов), стало `Filter: (is_active AND … AND
(NOT (hashed SubPlan 1)))` с `Index Only Scan using catalog_product_nonpublic_id_idx`, а у
страницы — `external_data` не в списке колонок (отложен). Полные планы — в заметках сессий
`search-perf-2026-11-05/explain5_before.json` и `explain5_after.json`.

## SQL для проверки на проде (только чтение)

Запускать как `EXPLAIN (ANALYZE, BUFFERS) <SQL>;` в `psql`. Это только `SELECT`: данные не меняются,
но запрос выполняется по-настоящему, и «было» на проде может идти десятки секунд («кр» — 20 с).
Таблица `catalog_productsearchindex` на проде уже заполнена (#321), поэтому «стало» можно снять
до выкатки #322: SQL не зависит от версии кода. Значения в SQL — из модельного каталога, но в
запросах нет id и дат, только текст поиска.
