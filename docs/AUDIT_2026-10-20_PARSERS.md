  карточек на настоящих сайтах. Пробы шли из локального Docker, без прокси и

- **Разбор кода** парсеров и общего пути сохранения (`services.py`, `tasks.py`,

## Исправлено кодом

Все исправления, кроме текста ошибки Bershka, закрыты тестами, которые падают
на старом коде.

### [PR #116](https://github.com/Mr-Fulani/PharmaTurk/pull/116) «Парсеры: живые баги» (`fix/parsers-live-bugs`)

1. **UmmaLand: цена ×10 / ×100.** Значок «-20%» лежит внутри блока цены, и
   «768 ₽ -20%» превращалось в 76 820. Карточку использует и проверка
   предложения при открытии товара. Защита от аномальных цен срабатывает
   только при отношении больше 20, поэтому скидка меньше 10 % (цена ×10)
   проходила. Распроданная книга получала остаток 3, теперь 0.
2. **LCW: название с ценой.** Рекламный og:title («Tişört - LC WAIKIKI -
   359,99 TL») пропускается, полное название берётся из `<title>`. Для уже
   испорченных 999 названий есть команда `repair_lcw_names`
   ([CATALOG_MAINTENANCE_COMMANDS.md](CATALOG_MAINTENANCE_COMMANDS.md)). Её
   пробный прогон с прода на 5 товарах прошёл: «Parfüm - Markalar - 669,90 TL»
   → «AVON 100 ml Erkek Parfüm - S000188228-10231».
3. **LCW: дубль цвета после редиректа.** Старые id цветов отвечают 301 на
   другой цвет. Итоговый URL теперь запоминается, и уже собранный цвет
   пропускается.
4. **Zara: снятая карточка (404/410) обрывала обход категории** и трижды
   повторяла тот же чанк. Теперь она пропускается.
5. **IlacFiyati: «тихий успех».** Страница каталога без блока «Arama
   Sonuçları» — ошибка, а не «каталог закончился». На живом сайте заголовок
   есть и за последней страницей, и при пустом фильтре.
6. **Bershka/P&B/MD:** ошибка для категории без `?celement=` говорит, какой
   адрес вставить.
7. **Instagram: вход.** При «Checkpoint required» парсер больше не продолжает
   молча без входа (что давало непонятный 401). Ошибка говорит, что делать.
   Если в cookies конфига есть `sessionid`, вход по паролю не выполняется:
   повторные входы с сервера и вызывают такие проверки.

### [PR #114](https://github.com/Mr-Fulani/PharmaTurk/pull/114) «Путь сохранения» (`fix/scraper-save-path`)

1. **Ложные скидки.** Раньше `old_price` при любой смене цены или валюты
   заполнялся прежней ценой: в парсере, нормализаторе каталога, рыночных
   проверках лекарств и БАДов и в IKEA. Теперь это только зачёркнутая цена
   источника и только если она выше текущей (`apps/catalog/utils/old_price.py`).
   У лекарств поле пустое. Накопленные значения снимает команда
   `clear_heuristic_old_prices`. Отчёт на проде: 4317 товаров, видимая
   «скидка» у 920.
2. **Настоящие скидки источников.** Используются `oldPrice` размеров /itxrest
   (Bershka/P&B/MD), `oldPrice` цвета Zara и `.product-old-price` UmmaLand.
3. **FLO: завышенная цена.** У FLO `price` — цена без скидки, а продаётся
   товар за `special_price`. Её показывают страница и JSON-LD: 2 299,99 вместо
   2 799,99. Теперь цена — `special_price`, а `price` идёт в зачёркнутую цену.
4. **БАД IlacFiyati по прямой ссылке.** Корень «Медицина» из конфигурации
   делал его лекарством: существующий БАД пропускался, новый создавался
   лекарством. Теперь для `/takviye-edici-gida/<товар>` тип — БАД, а категория
   уже сохранённого товара не меняется.
5. **Цвет принадлежит одной карточке.** id группы LCW/FLO — минимальный id
   цвета, и он «плывёт». Перед созданием товара теперь ищется карточка,
   которой уже принадлежат цвета группы. Такая карточка объединяется с группой,
   цвета с неё не снимаются. Цвет чужой карточки не копируется. Сейчас на
   проде дублей цветов нет — это защита на будущее.
6. **«Обновление заглушек» (тип задачи `stub_refresh`) реально заполняет
   заглушки.** Раньше задача отчитывалась «обновлено», но заглушка оставалась
   без цены и картинки. Причина: заглушка наследует МНН родительского
   препарата («amoksisilin»), а в карточке аналога написано иначе
   («Amoksisilin trihidrat»). Сверка видела конфликт и пропускала товар.
   Теперь у заглушки сверяется только штрихкод. Задача идёт тем же путём, что
   обычный прогон (категория, бренд, загрузка картинок), а «пропущено»
   считается пропуском.
7. **Цена 0 при обновлении** больше не пишется на витрину (§5.1).
8. **Итог прогона не откатывает правки админа** (сохраняются только поля
   статистики). **Успех снимает «Ошибку»**: статус «Активен» нужен обновлению
   карточек, akakce и рыночной проверке лекарств.
9. **AI-названия вариантов** у товара с применённым AI-результатом не
   перетираются при перепарсинге (§3.7).
10. **Поиск дублей** (понедельник 04:30) читает только нужные поля — раньше
    это был риск OOM на воркере с лимитом 640 МБ.
11. **HTML-заглушка CDN** не сохраняется в R2 как `.jpg`.

### Ветка `fix/parser-media-pipeline` «Медиа парсеров»

1. **User-Agent.** CDN LC Waikiki и FLO (mncdn) отвечают 422 без браузерного
   User-Agent, а `ScraperConfig.user_agent` по умолчанию пуст.
   `download_and_optimize_parsed_media` шлёт браузерный UA в HEAD, GET и
   Range-фолбэке, если вызывающий не задал свой.
2. **Фото цветов одежды и обуви** (`fashion_variants`) идут тем же путём, что
   цвета IKEA: лимит `max_images_per_product`, оптимизатор, одна загрузка на
   URL, общий с корневой галереей. Pre_save-сигнал их больше не качает.
   Строки цветов, которые раньше сохранил сигнал (`image_url` — адрес
   источника), узнаются по отпечатку этого адреса в имени parsed-файла,
   поэтому галереи не пересоздаются. Если у цвета больше фото, чем
   `max_images_per_product`, при первом проходе лишние уйдут.
3. **Повторный проход не качает фото заново.** Перед загрузкой берётся уже
   сохранённая копия того же исходного URL у этого товара: галерея — по
   `external_data.parser_media_manifest` товара, цвета — по такому же
   manifest варианта и по строкам с адресом источника. Файл, которого нет в
   хранилище, качается заново. Товар определяется по единственному совпадению
   `external_id`. Если группа LCW/FLO сменила id, фото качаются, как раньше.

## Расписание, память, скорость

- **Расписание.** По расписанию идут только `cleanup_old_sessions` (каждый
  день в 04:20) и поиск дублей (понедельник 04:30, только кандидаты). Обход
  каталогов — вручную из админки или через обновление карточки при открытии.
- **Память.** Парсеры обрабатывают товары по одному, генераторами. Исключение —
  UmmaLand, но это 103 книги. Самым тяжёлым был поиск дублей — исправлено.
  Скачивание медиа держит файл целиком в памяти (буфер до 200 МБ).
- **Скорость на одну карточку** (живые пробы): IlacFiyati 2,5–3 с, FLO 3 с,
  Zara/P&B 3 с, Massimo Dutti 12 с с прогревом bm-verify, IKEA 6 с, LCW ~30 с.

   `--apply --backup <файл>`: снимаются 4317 ложных old_price.
