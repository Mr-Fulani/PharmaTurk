# Тема оформления и блоки главной в админке

Решение владельца 12.11.2026: тема оформления сайта и состав главной страницы
настраиваются в админке, без программиста. Содержимое блоков (баннеры, карточки
брендов с их SEO, разделы, отзывы) настраивается там же, где и раньше, и при
выключении блока не теряется.

## Экраны админки

**🎨 Оформление — Тема сайта** (`apps.settings.SiteAppearance`, одна запись).
Выбор темы: `cream` — «Кремовая», прежний вид (по умолчанию); `iznik` — «Изник»;
`green` — «Зелёная аптека».

**🏠 Главная — Блоки (показ и порядок)** (`apps.settings.HomeBlock`). В списке у
каждого блока галочка «Показывать» и число «Порядок»: блоки идут сверху вниз по
возрастанию. Добавить или удалить блок в админке нельзя — набор задан кодом.

| Ключ | Блок |
|---|---|
| `main_banner` | Баннер 1 — главный |
| `brands` | Популярные бренды |
| `banner_after_brands` | Баннер 2 — после брендов |
| `categories` | Категории товаров |
| `banner_before_footer` | Баннер 3 — после категорий |
| `bestsellers` | Хиты продаж |
| `sourcing` | «Найдём любой товар» |
| `recommendations` | «Вам может понравиться» |
| `banner_after_popular` | Баннер 4 — после хитов |
| `testimonials` | Отзывы покупателей |
| `facts` | «Как работает Mudaroba» |

Порядок по умолчанию — порядок главной на 12.11.2026 (миграция `settings.0005`).

Блоки «Популярные бренды» и «Категории товаров» — это ещё и ссылки на разделы
для поисковиков, «Как работает Mudaroba» — текст для поисковиков и ИИ-поиска:
выключение этих блоков убирает их и из HTML главной.

## Галочка блока отзывов

Раньше блок отзывов включался на экране «💬 Отзывы — Настройки блока»
(`feedback.TestimonialSectionSettings.show_on_homepage`). Теперь это блок
`testimonials`: значение галочки перенесено миграцией, прежний экран убран.
Адрес `GET /api/feedback/testimonials-section-settings` оставлен и отвечает
значением блока — для сборок фронтенда, выпущенных до перехода главной на
`settings/appearance`. Таблица прежней настройки в базе
осталась и больше не используется.

## API

`GET /api/settings/appearance` — открытый, без авторизации:

```json
{
  "theme": "cream",
  "home_blocks": [
    {"key": "main_banner", "is_enabled": true},
    {"key": "brands", "is_enabled": true}
  ]
}
```

`home_blocks` отсортирован по «Порядку».

## Как это читает сайт

- Тему читает `_document.tsx` и ставит `data-skin` на `<html>`
  ([DESIGN_THEMES.md](DESIGN_THEMES.md)).
- Главная (`pages/index.tsx`) получает в `getServerSideProps` список видимых блоков
  в порядке показа (`homeBlocks`) и рисует их из словаря `homeBlockNodes` — по
  одному узлу на ключ. Отдельного запроса галочки отзывов больше нет.
- Разбор ответа — `lib/siteAppearance.js`: неизвестные ключи отбрасываются; блок,
  которого нет в ответе, показывается после перечисленных.
- Настройка запрашивается не чаще раза в минуту на процесс, при сбое бэкенда
  остаётся последнее удачное значение. Если настройки не получены ни разу —
  прежняя главная без блока отзывов (он и раньше скрывался при сбое).
- Изменение видно на главной после истечения её кэша в CDN: около минуты и до
  шести с `stale-while-revalidate`.

## Новый блок главной

1. Значение в `HomeBlock.Key` и миграция схемы (`makemigrations`).
2. Отдельная миграция данных с `get_or_create` для нового ключа — без неё блока
   нет ни в админке, ни в API (тест `test_every_home_block_key_is_seeded`).
3. Ключ в `HOME_BLOCK_KEYS` (`frontend/src/lib/siteAppearance.js`) и узел в
   `homeBlockNodes` главной: без узла фронтенд не соберётся (тип `Record<HomeBlockKey, …>`),
   расхождение списков с бэкендом ловит `siteAppearance.test.mjs`.

Тесты — `backend/apps/settings/tests/test_site_appearance.py`,
`frontend/src/lib/siteAppearance.test.mjs`, порядок блоков на странице —
`frontend/src/lib/homepageBrands.test.mjs`.
