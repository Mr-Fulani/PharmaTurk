# Порядок «Популярные» по спросу из поиска

С 25.11.2026 список лекарств (и, когда появятся цифры, БАДов) в порядке «Популярные» начинается с
товаров, которые чаще ищут в поисковиках, по убыванию числа запросов. «Популярные» — порядок по
умолчанию в этих разделах и подкатегориях (`frontend/src/lib/catalogQuery.js`).

## Как устроено

- Таблица **«Спрос из поиска»** (`SearchDemand`, `apps/catalog/models_search.py`): раздел, начало
  названия товара (`MAJEZIK`, `TYLOLHOT`, `CLEOCIN T`), запросов в месяц, заметка.
- Спрос входит старшим разрядом в готовое число `sort_rank` (`services/catalog_sort_rank.py`):
  `спрос × 4 000 000 + цена/наличие × 1 000 000 + «Рекомендуемый» × 100 000 + интерес на сайте × 10 + качество карточки`.
  Решения владельца 25.11.2026: товар со спросом стоит выше остальных, даже если его нет в наличии
  или нет цены; метка «Ввоз ограничен» на место не влияет; товары без данных о спросе идут следом в
  прежнем порядке.
- «Спрос» в формуле — ступень 1…500: место частоты среди разных частот раздела. Пока разных частот
  не больше 500, порядок строго по числу запросов. 500 ступеней помещаются в прежнюю колонку,
  поэтому колонка и индексы (миграции 0212, 0214) не менялись.
- Совпадение: первые 1–3 слова названия карточки, склеенные без пробелов и дефисов, равны началу из
  таблицы. `TYLOLHOT` подходит к «TYLOL HOT D…», `A-FERIN` — к «A-FERIN…», `PAROL` — к «PAROL-K», но
  не к «PAROLEX». Формы одного названия получают одинаковый спрос; между ними порядок прежний.
- Пересчёт — ночная задача `catalog.recompute_sort_ranks` (04:50), кнопка в админке или команда.
  Запись через `bulk_update`: `save()` карточек не вызывается, `Product` и `updated_at` не меняются.

## Скорость

Страница списка таблицу спроса не читает: запрос тот же (`ORDER BY sort_rank DESC, id DESC`), идёт
по тому же частичному индексу. Тест `test_popular_list_puts_searched_names_first_without_extra_queries`
проверяет, что число запросов к базе не меняется. Замер 25.11.2026 на локальной копии с 13 301
названием: запрос списка 0,2 мс до и 0,1 мс после (Index Only Scan `catalog_medicine_nonstub_rank_idx`),
ответ API 24 карточек — 0,34 с до и 0,27 с после (разброс замера). Пересчёт всех лекарств — 4–5 с.

## Как обновлять

Админка → «Источники и проверки» → **«Спрос из поиска»**:

1. «Добавить» — раздел, начало названия латиницей, запросов в месяц → «Сохранить». Число можно
   менять прямо в списке (столбец «Запросов в месяц» → «Сохранить» внизу).
2. Порядок обновится ночью. Сразу: отметить галочкой любую строку → в поле «Действие» выбрать
   «Пересчитать порядок „Популярные“ сейчас» → «Выполнить».
3. Выключить для названия — удалить строку (или поставить 0). Выключить совсем — удалить все строки
   и пересчитать: порядок вернётся к прежнему.

Командами:

```bash
manage.py import_search_demand apps/catalog/data/search_demand_medicines_2026-10-23.csv           # показ
manage.py import_search_demand apps/catalog/data/search_demand_medicines_2026-10-23.csv --apply   # запись
manage.py import_search_demand файл.csv --type supplements --apply                                 # БАДы
manage.py recompute_sort_ranks            # показ: сколько товаров сменит место, первые 20 до и после
manage.py recompute_sort_ranks --apply    # запись нового порядка
```

Файл — CSV со столбцами `name,frequency` и необязательным `note`. Загрузка добавляет новые строки и
обновляет частоту у существующих; строки, которых нет в файле, не трогает.

## Данные

`backend/apps/catalog/data/search_demand_medicines_2026-10-23.csv` — 104 названия из SEO-ядра
лекарств (Вордстат, 23.10.2026, кластеры «Препарат: …», суммарная частота кластера). На 25.11.2026
им соответствуют 345 карточек из 13 301. По БАДам, обуви и одежде числа запросов не собраны
(`reports/supplement-seo-core-2026-11-07.md`, `reports/superstep-seo-core-2026-11-05.md` — только
подсказки и Trends); у обуви и одежды нет и поля `sort_rank`.

## Выкатка и откат

Миграция `0250_search_demand` создаёт пустую таблицу (сеть и R2 не нужны). После выкатки: бэкап →
`import_search_demand … --apply` → `recompute_sort_ranks` (показ) → `recompute_sort_ranks --apply`.
Откат данных: удалить строки таблицы и выполнить `recompute_sort_ranks --apply`.
