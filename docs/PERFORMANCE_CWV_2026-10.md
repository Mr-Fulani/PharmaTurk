# Скорость и Core Web Vitals — октябрь 2026

Цель: зелёные Core Web Vitals на телефоне (LCP < 2,5 с, INP < 200 мс,
CLS < 0,1) для главной, разделов и карточек, быстрый ответ сервера.

## Как мерить

- **Официально — PageSpeed Insights** (https://pagespeed.web.dev, «Мобильные
  устройства»). Лабораторный Lighthouse на серверах Google и полевые данные
  Chrome (CrUX) за 28 дней. API PageSpeed без своего ключа упирается в квоту,
  поэтому — через веб-страницу. Один отчёт считается 1–3 минуты.
- **Локально — Lighthouse 12.6 mobile** (`npx lighthouse … --only-categories=performance`),
  только чередующимися парами A/B и минимум по 3 прогона. Параллельно ничего
  не собирать: `npm ci` или `next build` рядом раздувают TBT в 5 раз.
- **Локальная prod-сборка для A/B:** `next start` на Node 22
  (`/opt/homebrew/opt/node@22`) с `INTERNAL_API_BASE=https://mudaroba.com`.
  Перед ней нужен мини-прокси, как nginx на проде: `/api/*` → прод, остальное
  → Next. Иначе `/api/catalog/proxy-media/?…` уходит в 308-редирект Next, а
  клиентские запросы API отвечают 500. Без прокси картинки товаров и поиск
  локально не работают, и замер ничего не показывает.
- **Помехи headless Chrome:** в части прогонов первая отрисовка случайно
  задерживается до ~2,5 с, даже когда HTML, CSS и картинка загружены к 0,6 с.
  Lantern превращает это в «Render Delay» и LCP 4–6 с. Так было и до правок
  (корзина, карточки лекарств). Это не регрессия: смотреть медианы и PageSpeed.
- **Origin без кэша Cloudflare:** запрос с cookie `currency=…` идёт мимо кэша
  (правило «HTML respect origin»). Так меряется время SSR.

### Почему шрифт сдвигал вёрстку

`InkVerse.woff2` (62 КБ) браузер находил только после разбора CSS. Первая
отрисовка шла системным шрифтом, после подмены текст перестраивался. Сильнее
всего — в кнопке «Не можете найти…» в шапке раздела и в заголовке карточки:
там жирный текст заглавными, а заглавные и цифры у InkVerse заметно уже
системных. На лишнюю строку смещалась вся страница ниже.

### Подмножество шрифта

Предзагруженный шрифт делит канал с CSS и главной картинкой, поэтому его вес
напрямую влияет на LCP. Файл собран так (в нём остались латиница с турецкими
буквами, кириллица, знаки препинания и валют):

```bash
python3 -m fontTools.subset InkVerse.woff2 --unicodes="U+0000-00FF,U+0100-017F,U+0400-04FF,U+2000-206F,U+20A0-20CF,U+2116,U+2122,U+2190-2199,U+2212" --flavor=woff2 --no-hinting --layout-features='*' --output-file=InkVerse-v2.woff2
```

Для woff2 нужен модуль `brotli` (`pip install brotli`). Файлы в `/fonts/`
кэшируются как `immutable`, поэтому новый шрифт — всегда под новым именем: и в
`@font-face` (`globals.css`), и в `preload` (`_document.tsx`).

## Проверили и отказались

- **Запасной `@font-face` с метриками InkVerse** (`size-adjust` + `ascent-override`
  по Arial). Для обычного русского текста ширина совпадает до 2 %, но CLS не
  изменился (0,128 → 0,128): заглавные и цифры у шрифтов слишком разные.
- **Встраивание критического CSS** (`experimental.optimizeCss`, пакет `critters`).
  PageSpeed обещает 0,5–0,7 с за «render-blocking CSS». В A/B LCP не улучшился,
  FCP — в пределах шума. Цена: critters обрабатывает HTML на каждом SSR — 90–150 мс
  CPU на быстром Mac, у раздела лекарств с большим DOM 750 мс, плюс пакет устарел.
- **Баннеры главной напрямую с CDN** — проверено в октябре раньше
  ([PR #141](https://github.com/Mr-Fulani/PharmaTurk/pull/141)): мобильный LCP хуже на 0,6 с.

## Осталось / идеи

1. **Сериализация карточек одежды и мебели — ~50 мс на товар.** `view=card`
   строит полный сериализатор и только потом сжимает ответ (`compact_card_product_payload`).
   Лекарства и БАДы идут через `SimpleDomainCardSerializer` — 0,3–0,5 с на
   страницу. Нужен подсчёт SQL на локальной БД с данными; чтение прода из
   агентской сессии заблокировано.
2. **`/api/catalog/products?category_slug=medicines&ordering=popular` — 17–32 с.**
   Фронт его не вызывает (лекарства идут через `medicines/products`), но такой
   запрос надолго занимает воркер. Это «популярные» по общему эндпоинту:
   `-is_featured` без частичного индекса по `catalog_product`.
3. **Сторонние запросы, которые добавляет сам Cloudflare:** Web Analytics
   (`static.cloudflareinsights.com/beacon.min.js`, 10 КБ, ~70 мс CPU) и Email
   Obfuscation (`email-decode.min.js`). Выключаются в панели Cloudflare
   (Analytics → Web Analytics, Scrape Shield). Решает владелец: правило сайта —
   аналитика только GA4.
4. **Ролик IKEA с www.ikea.com (3,3 МБ)** в карточке раздела мебели проигрывается
   автоматически (`InViewAutoplayVideo`). Это решение дизайна, на телефоне — трафик.
5. **Переводы:** весь `common.json` (86 КБ, 1606 ключей) встроен в каждую страницу.
   Деление на namespace — большой рефакторинг вызовов `t()`.
6. `@import` Google Fonts (Poppins) в `globals.css` стоит после правил, и браузер
   его игнорирует: Poppins никогда не грузился. Мёртвая строка, на скорость не влияет.
