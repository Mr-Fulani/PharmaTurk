# IndexNow: быстрое оповещение Bing и Яндекса

С 02.11.2026. Код: `backend/apps/catalog/services/indexnow.py`, модель
`backend/apps/catalog/models_indexnow.py` (миграция `catalog/0234`), задача
`catalog.indexnow_submit` (`CELERY_TASKS.md`), тесты `apps/catalog/tests/test_indexnow.py`.

## Зачем

Без IndexNow Bing и Яндекс узнают о новой карточке или снятом товаре, только когда
сами перечитают sitemap или зайдут на страницу — бывает через дни и недели.
[IndexNow](https://www.indexnow.org/documentation) — общий протокол: сайт сам шлёт
список изменившихся адресов, и все участники (Bing, Яндекс и др.) получают его
через один запрос на `https://api.indexnow.org/indexnow`. Google в IndexNow не
участвует, для него по-прежнему sitemap.

## Что отправляется

Только страницы товаров — те же, что в секциях sitemap `products-<домен>`
(`frontend/src/pages/sitemaps/[section].tsx`): активные товары всех 18 доменов, без
копий вариантов и заглушек лекарств. Для каждой страницы уходят оба адреса —
`https://mudaroba.com/product/...` и `https://mudaroba.com/en/product/...` (EN-версия
стоит в sitemap как hreflang-альтернатива). Путь строит `build_canonical_path`, как
в canonical карточки.

Страница уходит, если с прошлой отправки:

- товар **новый** на витрине (или вернулся после снятия);
- изменились **название, описание, наличие** (`is_available`) или **перевод RU/EN**
  (название и описание в таблице переводов домена);
- товар **пропал с витрины**: снят (`is_active=false`), удалён, стал копией варианта
  или заглушкой. Поисковик перечитает адрес и увидит 404 или 301. Смена slug — это
  новая страница плюс пропавшая старая (она отдаёт 301).

**Не отправляется** изменение цены, зачёркнутой цены, картинок, атрибутов и SEO-полей.
Цену каждое утро пересчитывает курс, и `updated_at` меняется почти у всего каталога,
поэтому задача смотрит не на `updated_at`, а на отпечаток (MD5) значимых полей,
посчитанный в базе. Отпечаток последней отправки хранит таблица `IndexNowUrlState`.
Категории, бренды, услуги, страницы препаратов и блог не отправляются — их
поисковики берут из sitemap.

## Когда

Beat раз в час, в `:45` по МСК (`catalog-indexnow-submit`). Порядок за запуск: новые,
затем пропавшие, затем изменённые. За запрос — не больше 10 000 URL (предел протокола),
за сутки — не больше `INDEXNOW_DAILY_URL_LIMIT` (10 000 URL = 5 000 страниц); остаток
ждёт следующего часа или следующих суток.

**Первый запуск** после включения ничего не отправляет: таблица пуста, задача
запоминает весь каталог как есть (`status: baseline`). Отправки начинаются со
следующего часа и касаются только изменений после включения.

**Ошибки.** Успех — ответ 200 или 202 (202: ключ ещё проверяется). Ответы 400, 403
(ключ не найден или не совпал), 422 (адреса не с этого сайта), 429 (слишком часто) и
сбой сети пишутся в журнал (`IndexNow: ответ …`), задача не падает. Неотправленные
страницы не помечаются и уходят при следующем запуске; на 429 запуск
останавливается до следующего часа.

**Нагрузка.** Каждый запуск читает название, описание и переводы всех активных товаров
и считает MD5 в Postgres; в Python приходят только slug и 32-символьный отпечаток.
Служебные строки исключаются подзапросом по частичным индексам миграции 0217, без
условий на `external_data` в основном запросе (тест на `EXPLAIN` в
`test_indexnow.py`). Если запуск станет заметен на графиках базы — реже ставить
расписание в `CELERY_BEAT_SCHEDULE`.

## Ключ

Ключ публичный, не секрет: `4fccd8201e121b6208b4c72fea513b6a`.

- Файл `frontend/public/4fccd8201e121b6208b4c72fea513b6a.txt` с самим ключом; Next.js
  отдаёт его как `https://mudaroba.com/4fccd8201e121b6208b4c72fea513b6a.txt` (nginx
  проксирует `/` во фронт, как `robots.txt`).
- В запросе — `keyLocation` с этим адресом; по нему Bing и Яндекс проверяют, что
  адреса шлёт владелец сайта.
- В backend — `INDEXNOW_KEY` (значение по умолчанию то же). Сменить ключ: новый файл
  в `frontend/public/`, новое значение по умолчанию в `settings.py` (или
  `INDEXNOW_KEY` в `.env`), релиз фронта раньше бэкенда. Старый файл удалить после.

## Включение

Выключено, пока в `.env` прода нет `INDEXNOW_ENABLED=true`. На проде включено 02.11.2026
(релиз 76cd1e6d).

1. Релиз с миграцией `catalog/0234` (полный, не сокращённый — новая таблица).
2. Проверить, что ключ отдаётся (ответ 200 и строка ключа):

   ```bash
   curl -s https://mudaroba.com/4fccd8201e121b6208b4c72fea513b6a.txt
   ```

3. В `.env` прода:

   ```dotenv
   INDEXNOW_ENABLED=true
   # необязательно, по умолчанию:
   # INDEXNOW_DAILY_URL_LIMIT=10000
   ```

   Адрес сайта берётся из `FRONTEND_SITE_URL` (на проде `https://mudaroba.com`).
4. Пересоздать `celeryworker` и `celerybeat` (новое окружение подхватывается только
   при пересоздании).

Выключить — `INDEXNOW_ENABLED=false` и пересоздать те же контейнеры. Таблица
остаётся; при повторном включении накопленные за паузу изменения уйдут в пределах
дневного лимита.

## Как проверить

- Ручной запуск (первый — `baseline`, дальше — `ok` со счётчиками `new`, `changed`,
  `gone`, `submitted_urls`):

  ```bash
  docker compose -p mudaroba exec backend poetry run python manage.py shell -c \
    "from apps.catalog.services.indexnow import submit_changed_products as s; print(s())"
  ```

- Журнал воркера: `docker compose -p mudaroba logs celeryworker | grep IndexNow`.
- Сколько страниц ушло сегодня:

  ```bash
  docker compose -p mudaroba exec backend poetry run python manage.py shell -c \
    "from django.utils import timezone as t; from apps.catalog.models import IndexNowUrlState as S; \
  print(S.objects.filter(submitted_at__date=t.localdate()).count())"
  ```

- Bing Webmaster Tools → IndexNow: принятые адреса появляются в течение суток.
  Яндекс.Вебмастер — переобход этих адресов в статистике обхода.
