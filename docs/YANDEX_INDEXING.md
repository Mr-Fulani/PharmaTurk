# Индексация в Яндексе: разбор 09.11.2026

Вопрос: почему в Яндекс Вебмастере «Страниц в поиске — 435» при 28 457 адресах в sitemap.
Смотрели Вебмастер (аккаунт fulani.dev) и сайт снаружи с User-Agent YandexBot.

## Главная причина — сбой у самого Яндекса

С 7–8 октября 2026 у Яндекса выведены из строя дата-центры (Сасово, Калуга, 11.10 —
Владимир; новость `yandex.ru/company/news/09-10-2026-01`). На 09.11 в Вебмастере:

| Раздел | Состояние |
| --- | --- |
| Сводка, «Мои сайты» | «данные временно не обновляются»; последнее обновление поиска — **7 октября** |
| Страницы в поиске | список изменений до 07.10, вкладка «Исключённые страницы» и выгрузка недоступны |
| Статистика обхода | инструмент недоступен целиком |
| Файлы Sitemap | «только для чтения»: переотправить нельзя |
| Диагностика | выгрузка и обновление недоступны |
| Проверка ответа сервера | работает «нестабильно», но отработала |

Цифры 595 / 435 — снимок на 7 октября. Что Яндекс делал с сайтом после этого, Вебмастер
не показывает. До восстановления Яндекса со стороны сайта эту часть не ускорить.

## Что было до сбоя (по данным Вебмастера)

- **Sitemap прочитан, ошибок нет.** Индекс — 10.10, секции — 04.09–10.10, статус «ок» у всех.
  Яндекс знает ~27 тыс. адресов (лекарства 12 143, БАДы 7 882, мебель 2 064, одежда 1 009 …).
  Пустые секции (electronics, medical-equipment, auto-parts — 0 адресов) тоже «ок», не ошибка.
- **Обходил медленно и в основном «по счётчику Метрики»**, а не по sitemap: почти все
  страницы в списке изменений пришли с пометкой «Счётчик Метрики», реже «Индексирование».
  ИКС — «недостаточно данных», кликов из поиска — 2. Сайт молодой: Яндекс даёт такому
  маленький лимит обхода.
- **Снимки в индексе старые**: страницы попали в поиск с турецкими заголовками
  («WELLBUTRIN XL 150 MG 30 YAVAS SALINIMLI FILM KAPLI TABLET», «BAGGY FIT JEAN - Kömür»).
  Сейчас у них русские title — Яндекс увидит после переобхода.
- **Исключения «Малоценная или маловостребованная страница»** в видимой части списка:
  пустые разделы (`/categories/auto-parts`, `/categories/medical-equipment` — теперь
  noindex, в sitemap их нет), `/categories/blood-hematology`, товары с турецкими
  названиями (FLO, Zara), `/brand/nike`, `/en/categories/headwear`. Полный список с
  числами — вкладка «Исключённые», она недоступна.
- **Дубли лекарств**: в поиске обе страницы одного препарата — `thiola-100-mg-100-tablet` и
  `thiola-100-mg-100-tb`, `loniten-…-tablet-…` и `loniten-…-tb-…` (одинаковый title, у каждой
  свой canonical; 09.11 обе пары отвечают 200). Это «близнецы» ilacfiyati
  ([ILACFIYATI_TWIN_PAGES.md](ILACFIYATI_TWIN_PAGES.md)). В списках `hide_ilacfiyati_duplicates`
  (138 пар скрыты 09.11) и в 129 сомнительных их нет. LONITEN стоит в отчёте
  `reports/ilacfiyati-twin-pages-2026-11-04.md` в разделе «что будет скрыто» — это команда
  `hide_ilacfiyati_twin_pages`; THIOLA нет ни в одном списке — проверить отдельно.
- Ограничений и нарушений нет («Безопасность и нарушения» — «Нет ограничений»).
- Рекомендации диагностики (обе с 08.04.2026): регион сайта не задан; организации нет в
  Яндекс Бизнесе.

## Сайт снаружи — в порядке

| Проверка | Результат |
| --- | --- |
| Настоящий робот Яндекса (Вебмастер → «Проверка ответа сервера», карточка Mounjaro) | 200, 584 мс, 291 КБ — Cloudflare не мешает |
| robots.txt | 200, Disallow только служебные разделы, `Sitemap:` указан; Clean-param не было |
| sitemap.xml и 23 секции | все 200, XML валиден, 28 457 адресов (товаров 27 512), дублей нет; лекарства 8,3 МБ / 12 342 адреса (предел 50 МБ / 50 000) |
| Выборка 1 % товаров (270 адресов) | 270 × 200, canonical = адрес из sitemap, noindex нет; по одному запросу медиана 0,44 с |
| Не товары из sitemap (945 адресов) | 944 × 200; `/brand/jordan` один раз 500 при 12 параллельных запросах, повтор — 200 за 3,5–4,4 с |
| `/ru`, `/ru/...`, `www`, `http` | 301/308 на основной адрес; **исключение:** `http://mudaroba.com/` отдаёт 200 из кэша Cloudflare (на остальных адресах http → 308) |
| Фильтры/сортировка | `?sort=` — noindex + canonical на раздел; `?page=N` — self-canonical; `?utm_…` — canonical без метки |

## Что сделано в коде

`frontend/public/robots.txt`: `Clean-param` для меток `utm_*`, `yclid`, `ysclid`, `gclid`,
`fbclid`, `_openstat`. Метки `utm_source=vk&utm_medium=market` стоят во всех ссылках YML-фида
ВК (`yml_feed.py`), `utm_*` — в напоминаниях о заявке, `ysclid`/`yclid` дописывает сам Яндекс,
а Метрика (обход по счётчикам включён) передаёт роботу адреса вместе с метками. Без Clean-param
Яндекс обходит копии страницы с каждой меткой и тратит на них и без того маленький лимит.
Параметры сайта (`page`, `sort`, фильтры, `q`) в Clean-param не добавлять — тест
`src/lib/seoStatic.test.mjs`.

## Что делается в интерфейсе (по согласию владельца)

1. **Переотправить sitemap** (Индексирование → Файлы Sitemap) — сейчас невозможно, режим
   «только для чтения». Сделать, когда Яндекс снимет плашку. Безопасно.
2. **Переобход важных страниц** (Индексирование → Переобход страниц, 10 адресов в день):
   главная, `/categories/medicines`, `/categories/supplements`, `/how-to-order-medicines`,
   `/turetskaya-apteka`, `/dostavka-lekarstv-stambul`, `/drugs/majezik`, `/blog/top-tureckih-lekarstv`.
   Безопасно, но пока Яндекс восстанавливается, эффект сомнителен.
3. **Регион** (Представление в поиске → Региональность): сайт работает на всю Россию, регион
   «Россия» или не задавать. Решение владельца. Регион организации задаётся через Яндекс Бизнес
   (нужен адрес/контакты организации — тоже решение владельца).
4. **Clean-param** задаётся в robots.txt (сделано в коде), в интерфейсе Вебмастера его нет.
   Проверка — «Инструменты → Анализ robots.txt» после выкатки.
5. **Cloudflare → SSL/TLS → Edge Certificates → Always Use HTTPS** — включить, чтобы
   `http://mudaroba.com/` не отдавался из кэша как 200. Не Вебмастер, но влияет на «зеркала».

## Чего ждать

Пока Яндекс не восстановил дата-центры, числа в Вебмастере не изменятся. Когда плашки
пропадут: переотправить sitemap, проверить «Исключённые страницы» (доля «малоценных» и
дублей), «Статистику обхода» (сколько страниц в день и коды ответа). IndexNow
([INDEXNOW.md](INDEXNOW.md)) уже шлёт новые и изменённые товары через `api.indexnow.org` —
Яндекс получает их наравне с Bing.
