# SEO-тексты разделов через Claude

Команда `category_landing_seo` (сервис `apps/catalog/services/category_landing_seo.py`)
пишет для посадочной страницы раздела H1, title, description и SEO-текст на русском и
английском — те же поля перевода, что у медикаментов (`CategoryLandingSeoMixin`,
[MEDICINE_LANDING_PAGES.md](MEDICINE_LANDING_PAGES.md)). Медикаменты (ручные тексты,
миграция 0222) и услуги Стамбула команда не трогает.

Зачем: в Search Console 23.10.2026 — 3 782 «Просканирована, но не проиндексирована».
У разделов БАДов, одежды, обуви, мебели был только шаблон «Витамины | БАДы | Mudaroba»
и сетка товаров без текста.

## Как работает

1. **Факты из базы** (`collect_facts`): название RU/EN, родительские разделы, непустые
   подразделы, до 12 брендов по числу товаров, до 20 названий товаров. У БАДов —
   срок «доставка 7–21 рабочий день» (он же в карточках); у остальных сроков нет.
2. **Claude** (`ClaudeClient`, без запасного OpenAI) отвечает строго по JSON-схеме
   (structured outputs, `output_schema`) по системному промпту. Модель — `--model`;
   тексты 27.10.2026 пишет **Sonnet 5.5** (решение владельца): на пилоте Haiku без схемы
   ломал JSON у 3 из 5, а со схемой изредка выдавал мусор («## ЧЕРНОВИК…» ×8, «Mudaroba»
   дважды в title) и выдумки («U.S. Polo Assn. — турецкая марка», «уточните дозу для
   ребёнка у менеджера»). У Sonnet 5.5 размышления не выключаются (400) — адаптивные,
   `effort=medium`. Правила промпта: только факты, без чисел товаров и цен, без «лучший/скидки/бесплатно/гарантия»,
   без обещаний про здоровье и слов «лечение/лечить»; у БАДов — оговорка, что это не
   лекарство.
3. **Проверка кодом** (`validate_texts`): длины (H1 15–80, title ≤ 80 с одним
   « | Mudaroba», description 100–200, текст 140–420 слов, 1–3 подзаголовка `## `),
   запрещённые слова RU/EN (обещания про здоровье, оценки брендов, отзывы, «черновик»),
   числа от трёх цифр (кроме дозировок и фасовки: «1000 МЕ», «120 таблеток»), повтор
   фразы из трёх слов 4+ раз, кириллица в EN. При замечаниях — одна повторная попытка
   (`generate_checked`); черновик с замечаниями `apply` не примет. Смысловые выдумки код
   не ловит — каждый текст вычитывается человеком до `apply`.
4. **Запись** (`apply_texts`) — только в пустые поля, правки из админки не перетираются;
   прежние значения — в файл бэкапа. Нет EN-перевода — создаётся с названием `name_en`
   из фактов, если оно есть.

## Запуск (прод, отдельным контейнером)

```bash
# черновик пилота: 5 разделов, база не меняется
python manage.py category_landing_seo generate --model claude-sonnet-5-5 --roots supplements,shoes,furniture --limit 5 --out /tmp/pilot.json
# посмотреть, поправить промпт/файл, затем
python manage.py category_landing_seo apply --file /tmp/pilot.json --backup /tmp/pilot-backup.json --dry-run
python manage.py category_landing_seo apply --file /tmp/pilot.json --backup /tmp/pilot-backup.json
```

`--slugs a,b` — конкретные разделы, `--include-filled` — и с уже написанным текстом
(для перезаписи `apply --overwrite`). Откат — значения из файла бэкапа.

Порядок, как у всех AI-прогонов: пилот 5 → проверка человеком → правки промпта кодом →
следующие. Страницы обновятся после кэша категорий и Cloudflare.
