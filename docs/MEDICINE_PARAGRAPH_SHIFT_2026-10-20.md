# Сдвинутые переводы в памяти абзацев инструкций (20.10.2026)

Отчёт и порядок действий на проде. Код: `backend/apps/ai/services/medicine_paragraph_check.py`,
`paragraph_problems` / `check_paragraph_payload` в `medicine_memory.py`, команда
`medicine_paragraph_audit`. Общее описание памяти переводов — [AI_GUIDE.md](../AI_GUIDE.md).

## Что случилось

Абзацы клинических разделов переводятся пачками: десятки абзацев в одном JSON
`{"ru": {"1": …}, "en": {"1": …}}`. Модель иногда пропускает элемент и продолжает
нумерацию, и дальше каждому ключу достаётся перевод следующего абзаца — до конца
ответа. Иногда сдвинут только EN. Проверки до этого исправления сверяли лишь
дозировки с единицами, а у абзацев короче 20 букв не проверяли и язык, поэтому
такие переводы попадали в память и расходились по всем товарам с тем же текстом.

Порядок `pk` в памяти совпадает с порядком абзацев в запросе, поэтому сдвиг виден
по соседним записям:

| pk | исходник | перевод в памяти |
|---|---|---|
| 619 | Eğer reçeteli ya da reçetesiz herhangi bir ilacı … bilgi veriniz. | Храните VISCOTEARS в недоступном для детей месте и в упаковке. |
| 620 | 5. VISCOTEARS'IN SAKLANMASI | Храните при комнатной температуре ниже 25°C. |
| 621 | VISCOTEARS'ı çocukların göremeyeceği … saklayınız. | После использования сразу закройте крышку. |
| 622 | 25°C'nin altındaki oda sıcaklığında saklayınız. | После открытия тюбик следует использовать в течение 6 недель… |

Сдвиг есть и в синхронной обработке (пилот 18.10), и в Batch API (20.10).

## Масштаб (выгрузка прода 20.10.2026, только чтение)

- В памяти `medicine_paragraph` **270 945** записей; под подозрением **58 245 (21,5 %)**:
  20.10 (Batch API) — 57 649 из 269 342, 18.10 (пилот) — 596 из 1 603.
- Ручная проверка 120 случайных записей (RU и EN): чужой перевод у **29 (24 %,
  95 % ДИ ≈ 17–32 %)**. Команда помечает все 29; из 91 верной помечает 3, и одна из
  них — тоже брак (перевод потерял «günde 3-4 dozda» — «3–4 раза в день»).
- Помеченные только сдвигом по соседям (19 767): в выборке 24 из 25 — чужой перевод.
- Помеченные только правилами абзаца без подтверждения соседями (2 445): в выборке
  15 из 23 — брак; ложные — испорченный исходник («000 hastanın», «C'nin altında»,
  «l2 yaşından»), время («Akşam 7» → «19:00») и короткие термины («Bilinç karışıklığı (konfüzyon)» → «Confusion»).

### Цифры по правилам

«Серебряная» разметка без ручного труда: **верные** — 34 396 записей, где все числа
исходника, RU и EN совпадают (и не совпадают с соседями); **сдвинутые** — 3 189
записей, где числа RU и EN совпали с числами соседнего исходника, а не своего.
Ручная — 120 случайных записей выше (29 сдвинутых, 91 верная).

| правило | срабатываний | только оно | из них ещё и сдвиг | ложных на «верных» | найдено «сдвинутых» | ручная: найдено / ложных |
|---|---:|---:|---:|---:|---:|---|
| `heading_mismatch` — номер «N.» заголовка не в начале RU и EN | 873 | 57 | 88 % | 0,07 % | 4,6 % | 0/29, 0/91 |
| `number_mismatch` — все числа (не только дозировки) | 12 993 | 744 | 91 % | 0,03 % | 92 % | 2/29, 1/91* |
| `length_mismatch` — длина перевода к исходнику больше ×2 | 24 218 | 442 | 97 % | 0,22 % | 38 % | 13/29, 0/91 |
| `ru_en_mismatch` — числа или длина RU и EN расходятся | 3 478 | 57 | 85 % | 0,03 % | 0,1 % | 1/29, 0/91 |
| `concept_mismatch` — ≥2 понятия исходника (почки, врач, хранение…) не найдены | 12 747 | 438 | 95 % | 0,10 % | 20 % | 2/29, 0/91 |
| `frequency_mismatch` — «Yaygın olmayan:» ≠ «Нечасто:» | 704 | 79 | 86 % | 0,09 % | 1,8 % | 1/29, 0/91 |
| все правила абзаца вместе | 38 478 | — | 94 % | 0,50 % | 96 % | 15/29, 1/91* |
| `shifted` — сдвиг по соседям и по цепочке | 55 800 | 19 767 | — | 0,14 % | 96 % | 29/29, 2/91 |
| **итого** | **58 245** | — | — | 0,53 % | 98 % | **29/29, 3/91*** |

\* одна из «ложных» — настоящий брак (потеряно «3–4 раза в день»).

Нормализация, без которой правила давали много ложных: разделители тысяч
(«1.000» = «1 000» = «1,000»), «2,50» = «2.5», дроби («½» = «1/2»), римские
(«tip II» = «2 типа»; «IV» не число — это «внутривенно»), 1 и 0 не сравниваются
(«birinden» = «1 из», «once»), числа словами («üç», «трёх», «twice», «тысячи»)
только оправдывают цифру и сами расхождения не создают («her iki» — «оба»,
аббревиатура «TEN» — не 10), порядковые «1. günde» — не заголовок, а «Yaygın
akıntılı döküntüler (» — не метка частоты.

## Что изменено в коде

- `paragraph_problems` дополнен правилами таблицы выше (`item_problems`): новый
  перевод с такими признаками в память не попадает, абзац повторяется один раз,
  иначе раздел уходит в модерацию.
- `check_paragraph_payload` (обычная обработка и `medicine_paragraph_batch collect`)
  ищет сдвиг внутри ответа (`request_shift`): если перевод абзаца ближе к соседнему
  исходнику, чем к своему, отклоняется цепочка таких абзацев до ближайшего, который
  точно на месте (`shifted`). Отклонённые в обычной обработке переводятся повторно,
  после `collect` — при обработке товара.
- Команда `medicine_paragraph_audit` проверяет уже записанную память теми же
  правилами плюс сдвиг относительно соседних записей.

## Порядок действий на проде (запускает пользователь)

Все шаги, кроме 3, бесплатны. Перед шагом 2 нужен свежий бэкап БД (ежедневный —
[DB_BACKUP.md](DB_BACKUP.md)) и ≈ 100 МБ свободного места в `/tmp` контейнера
(отчёт и бэкап — по ≈ 50 МБ).

```bash
# 1. Отчёт, ничего не меняет (на выгрузке 20.10: 71 с и 54 МБ без учёта Django)
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py medicine_paragraph_audit --dry-run --report /tmp/paragraph_audit.jsonl
docker cp mudaroba-backend-1:/tmp/paragraph_audit.jsonl ~/backups/

# 2. Бэкап затронутых строк и перенос в namespace medicine_paragraph_suspect
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py medicine_paragraph_audit --backup /tmp/paragraph_audit_backup.json
docker cp mudaroba-backend-1:/tmp/paragraph_audit_backup.json ~/backups/

# 3. Повторный перевод вынесенных абзацев (платно; сначала оценка)
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py medicine_paragraph_batch submit --dry-run
```

После шага 2 память эти абзацы не находит: они переведутся заново при обработке
товара или пакетом (`medicine_paragraph_batch submit` / `collect`). Строки остаются
в БД (namespace `medicine_paragraph_suspect`, видны в админке «Память переводов AI»),
ручные правки (`updated_at` позже `created_at`) команда не трогает. Повторный аудит
заменяет старую копию абзаца в `_suspect` новой — старая уже лежит в прошлом бэкапе
и попадает в новый.

Откат шага 2: `manage.py loaddata /tmp/paragraph_audit_backup.json` — строки
вернутся в `medicine_paragraph` по `pk`. Если абзац за это время перевели заново,
загрузка упрётся в уникальность `(namespace, source_hash)` — новую строку сначала удалить.

4. Затронутые товары (списки выше) — переобработать после шага 3, например
   `ai_enqueue --ids <id,…> --limit 60 --force --dry-run`, затем без `--dry-run`.
   Ожидающие логи из списка не одобрять, а переобработать так же.
5. Повторить шаг 1: новые переводы проходят новые проверки, ожидается почти ноль.

## Что не сделано и риски

- Пороги подобраны по выгрузке 20.10. Около 3 % верных записей помечаются тоже —
  они просто переведутся заново: по факту пакета 20.10 ($7,73 за ≈ 270 тыс. абзацев)
  перевод 58 тыс. абзацев стоит ≈ $1,7.
- Правила абзаца отклоняют и перевод с «починенным» испорченным исходником
  («C'nin altında» → «ниже 25°C»): такой раздел уйдёт в модерацию.
- Причина сдвига — длинные ответы (до 20 000 символов, десятки абзацев в одном
  запросе, `PARAGRAPH_BATCH_CHARS`). Детектор их отсекает, но при той же доле
  сдвигов ≈ 20 % абзацев каждого прогона будет уходить на повтор. Уменьшение
  запроса стоит проверить пилотом (не входило в эту задачу).
