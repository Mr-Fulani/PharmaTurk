# Три режима парсеров: товар, категория, весь сайт

У каждого рабочего парсера три режима запуска. Akakce сюда не входит: это не
каталог, а проверка наличия БАДов при открытии карточки.

| Режим | Как запустить в админке | Что произойдёт |
|---|---|---|
| **1. Один товар** | «Задачи парсинга сайтов» → «Добавить». Тип «Товар или категория по ссылке», в «Ссылка» — адрес карточки товара | Спарсится и сохранится один товар (у одежды — со всеми цветами) |
| **2. Вся категория** | Тот же тип, в «Ссылка» — адрес страницы категории. «Макс. товаров» — больше, чем товаров в категории (например, 100 000) | Все страницы категории пройдут цепочкой запусков до конца или до «Макс. товаров». Пауза и «Продолжить» работают. Исключение — Bershka, Pull&Bear, Massimo Dutti: категория идёт одним запуском без чанков, не больше «Страниц за один запуск» × 12 товаров (ставить ≥ числа товаров / 12); «Продолжить» после паузы начинает её сначала, сохранённые товары идут как «пропущено» |
| **3. Весь сайт** | Тип «Весь сайт (все категории)», ссылка не нужна | Парсер сам находит категории сайта и обходит их по очереди, каждую — до конца (у Bershka, Pull&Bear, Massimo Dutti — в пределах «Страниц за один запуск» × 12). Прогресс: «Весь сайт: прогресс» в задаче |
| **Только изменения (IlacFiyati)** | Тип «Только изменения (IlacFiyati)», ссылка не нужна; «Макс. товаров» — 100 000 | Открываются только новые карточки и те, чья строка в листинге изменилась; пропавшие снимаются с продажи. Подробно — [ниже](#только-изменения-ilacfiyati) |
| **Instagram: пост** | «Задачи Instagram» → «Ссылка на пост» | Один пост |
| **Instagram: весь профиль** | «Задачи Instagram» → username, ссылку оставить пустой, «Максимум постов» не меньше числа постов профиля (до 5000) | Все посты профиля. Нужен вход: cookie `sessionid` в «Cookies» конфигурации парсера Instagram (пароль не нужен и не хранится — TD-016) |

Таблица «Как запустить» с примерами ссылок для каждого парсера есть прямо в
форме задачи (`apps/scrapers/modes.py`).

## Куда попадают товары в режиме «Весь сайт»

- Если в задаче выбрана «Целевая категория», все товары попадают туда.
- Если не выбрана, категория ищется в «Сопоставлениях категорий»
  конфигурации: адрес категории источника → наша категория. Если
  сопоставления нет, работает автоопределение парсера: IlacFiyati — лекарства
  и БАДы, FLO — тип обуви, IKEA — по категории и функции API. Если не сработало
  и оно, товар уходит в категорию по умолчанию из конфигурации.
- Для UmmaLand (книги, праздники, игры, канцелярия…) и магазинов одежды перед
  первым полным прогоном стоит завести сопоставления категорий, иначе всё
  уйдёт в категорию по умолчанию.

## Как это устроено

- **Режим определяется по ссылке**
  (`ScraperIntegrationService._run_parser_scraping`): карточка товара — один
  товар; страница категории — обход категории. Обход сохраняет каждый товар
  сразу и продолжается чанками («Страниц за один запуск») через
  `run_scraper_task`, пока парсер сообщает `has_more_pages`. Чанки — только у
  парсеров с `SUPPORTS_PAGE_CHUNKING` и `supports_page_chunking_for_url`
  (IlacFiyati, UmmaLand, Zara, LCW, FLO, IKEA); у Inditex-наследников флага
  нет, категория — один запуск.
- **Весь сайт** (`SiteScraperTask.task_type = "site"`). В первом чанке
  вызывается `parser.parse_categories()`. Список сохраняется в
  `SiteScraperTask.site_categories`, текущая категория — в
  `site_category_index`. Каждая категория идёт тем же обходом категории.
  Когда категория закончилась, `run_scraper_task` запускает следующую со
  страницы 1. Счётчики общие. Состояние обхода (`CatalogTraversalState`:
  «уже видели», «три страницы без новых товаров») у каждой категории своё
  (`services._catalog_scope`). Если бы оно было общим, категория, первые
  страницы которой повторяют соседнюю, останавливалась бы раньше времени.
  Товар из соседней категории просто обновляется ещё раз. Категория, упавшая
  после всех повторов, пропускается с ошибкой в задаче. Пустая категория
  (лукбук без карточек, `MalformedOfferResponse`) и 404 страницы категории
  (`CategoryPageNotFoundError`) не повторяются — обход сразу идёт к
  следующей (`tasks._category_content_error`). Блокировка доступа
  (401/403) останавливает весь обход. Пустой список категорий — понятная
  ошибка, а не «успех».
- **Только изменения** (`task_type = "changes"`) идёт той же цепочкой, что
  «Весь сайт» (`tasks.SITE_TRAVERSAL_TASK_TYPES`): этапы берутся из
  `parser.parse_change_sources()`, а сервис подставляет парсеру
  `ListingChangeTracker` (`changes_only=True`).
- Тип «Товар или категория по ссылке» без ссылки форма не примет. Раньше
  такая задача запускала старый обход «всех категорий» в памяти: без чанков,
  с сохранением только в конце.

## Категории сайта по парсерам

| Парсер | Откуда берутся категории для режима «Весь сайт» |
|---|---|
| IlacFiyati | два корневых каталога с полной пагинацией: `/ilaclar` и `/takviye-edici-gida` |
| UmmaLand | корневые разделы WooCommerce API без витринных подборок («Новинки», «Популярное») |
| Zara | дерево меню `/tr/tr/categories?ajax=true` (AJAX-транспорт, обычный HTML закрыт Akamai): листинги всех разделов, ~340. Промо-разделы (THE NEW, ÇOK SATANLAR, коллекции) тоже берутся, поэтому пересечение большое, а карточка Zara грузится по одной (≥ 2,5 с) — полный обход долгий |
| Bershka, Pull&Bear, Massimo Dutti | дерево категорий `/itxrest`: каждый узел с публичным адресом, и родитель, и дети (у Bershka часть товаров есть только у детей). ~260 / 350 / 490; у Massimo Dutti часть узлов — лукбуки, они могут быть пустыми |
| LC Waikiki | 12 корней каталога записаны в коде (`LcwParser.SITE_ROOT_PATHS`), подразделы — из `CategoryTree` страницы корня; ~50 категорий. Новый отдел на сайте нужно дописать в код |
| FLO | фильтр «kategori» страницы `/tum-kategoriler` (полное дерево): разделы второго уровня и корни без подразделов, ~130 |
| IKEA | разделы меню «Ürünler» (API `menuproduct`), ~22. «Tüm Mobilyalar» не берётся: поиск API отдаёт не больше 10 000 товаров на категорию. По выборке в разделы попадают ~95 % товаров |

Числа — живая проверка 21.10. Список ограничен: 500 категорий, у Inditex — 800
(`BaseScraper.MAX_SITE_CATEGORIES`). Пустой список — ошибка
`SiteCategoriesError`, а не «успех».

## Только изменения (IlacFiyati)

Полный обход IlacFiyati открывает каждую карточку (~20 тыс.), хотя большинство
не меняется. Режим «Только изменения» читает строки листинга — в них уже есть
название, штрихкод, цена, статус (AKTİF/PASİF) и тип рецепта — и открывает
карточку, только если строка отличается от запомненной.

**Как запустить.** «Задачи парсинга сайтов» → «Добавить»: конфигурация
IlacFiyati, тип «Только изменения (IlacFiyati)», ссылка не нужна, «Макс.
товаров» — 100 000 (считаются только открытые карточки), «Страниц за один
запуск» — 20–50. Пауза и «Продолжить» работают как у «Весь сайт». Для другого
парсера форма тип не примет.

**Три этапа** (в задаче — «Весь сайт / изменения: прогресс»):

1. **Лекарства `/ilaclar`**, все страницы листинга. Карточка открывается, если
   товара у нас нет, это заглушка аналога, товар у нас снят с продажи, а у
   источника AKTİF, или отпечаток строки (название, штрихкод, цена, статус,
   рецепт) отличается от запомненного. В первом проходе отпечатков ещё нет:
   строка сверяется с базой по названию источника (`source_name`) и цене;
   совпала — отпечаток запоминается без открытия карточки. Строка PASİF у
   товара, который у нас в продаже, — товар снимается с продажи; пассивные
   товары, которых у нас нет, не заводятся.
2. **БАДы `/takviye-edici-gida`** — так же.
3. **Sitemap `sitemap.xml.gz`** (один запрос, 34 624 адреса). Открываются
   ссылки, которых листинг в этом проходе не показал: новые товары и те, до кого
   листинг не достаёт — `/ilaclar` отдаёт только 1000 страниц (12 000 из
   ~12 465 активных лекарств), дальше снова первая страница. Наши товары в
   продаже, которых нет ни в sitemap, ни в листинге, проверяются запросом
   карточки: 404/410 или «İlaç Durumu: Pasif» — снимаются с продажи, иначе
   карточка сохраняется как обычно. Sitemap меньше 1000 карточек — ошибка, по
   нему никто не снимается.

**Что сохраняется.** Открытая карточка идёт обычным путём парсера: цена,
зачёркнутая цена, AI-тексты и пометка «изменился исходник»
(`ai_source_changed_at`) работают так же, как при полном обходе. Цена из строки
напрямую не пишется: карточка — один запрос (вкладки инструкции и аналоги
встроены в страницу), а единый путь сохранения важнее этой экономии.

**Снятие с продажи** ничего не удаляет: товар и доменная запись — «нет в
наличии», предложения источника — «нет в наличии» с кодом `inactive` (PASİF) или
`not_found` (404). Следующий успешный разбор карточки вернёт наличие.

**Где хранится.** Таблица `SourceListingRow` (парсер, ссылка, отпечаток, статус
у источника, ID прохода). Отпечаток открытой строки записывается только после
успешного сохранения карточки — упавшая откроется в следующем проходе. Код:
`apps/scrapers/base/listing_changes.py` (решение), `apps/scrapers/listing_changes.py`
(БД), `IlacFiyatiParser.parse_listing_rows` / `_parse_sitemap_changes`.

**Чего режим не видит.** Правку инструкции, картинок или аналогов без изменения
строки листинга. Поэтому раз в месяц — полный обход «Весь сайт» (автозапуска
нет, запускает владелец). Строки, сдвинувшиеся в листинге во время прохода,
подберёт sitemap-этап: любая активная ссылка, которую листинг не показал,
открывается.

**Только посмотреть.** `manage.py ilacfiyati_changes_probe` ничего не пишет:
проходит листинги и sitemap, печатает, сколько карточек откроется и сколько
товаров снимется с продажи, сколько это запросов и часов против полного обхода
([MANAGEMENT_COMMANDS.md](MANAGEMENT_COMMANDS.md)). `--pages 20` — быстрая проба
без sitemap.

**Цифры** (замер на проде 25.10.2026, `ilacfiyati_changes_probe` по реальной базе,
только чтение): страница листинга — 12 товаров, ~470 КБ, ≈ 2,8 с с задержками
конфигурации; карточка ≈ 2,7 с. Листинги — 1000 + 657 страниц, в sitemap 20 348
карточек.

| | Запросов | Время |
|---|---|---|
| Полный обход | ≈ 22 000 (1 657 страниц + 20 348 карточек) | ≈ 16,7 ч |
| «Только изменения», первый проход | ≈ 5 300 (1 659 листингов и sitemap + 3 667 карточек) | ≈ 4,1 ч |
| «Только изменения», дальше | ≈ 2 100 + изменившиеся строки | ≈ 1,6 ч + 2,7 с на строку |

Первый проход открывает больше: отпечатков ещё нет, и строка сверяется с базой.
Из 19 883 строк листингов совпали с базой 18 073; открываются 1 809 — 756 лекарств,
которых у нас нет, и 1 053 строки с другой ценой или названием. Ещё 466 активных
карточек листинг не показал (за 1000-й страницей), и 1 392 наших товара в продаже
нет ни в sitemap, ни в листинге — их проверит запрос карточки, и пассивные или
удалённые снимутся с продажи. Сколько из 1 392 снимется, станет видно только
после первого прохода.

## Описание товара

Описание не должно быть пустым. Если у источника нет текста описания, парсер
собирает его из характеристик карточки:

- **Bershka, Massimo Dutti** — `/itxrest` отдаёт пустой `description`.
  Описание собирается из атрибутов `DESCRIPTION` (их сайт показывает как
  описание), состава (`compositionDetail`) и ухода (`care`).
- **FLO** — у части обуви описания нет и на сайте, есть только блок
  «Ürün Özellikleri». Описание собирается из него: марка, модель, цвет, пол,
  материалы, подошва.

Настоящий текст источника всегда главнее. Старые товары задним числом не
перепарсиваются: описание появится при следующем проходе.

## Проверка после деплоя

У каждого парсера: 1–2 товара по ссылке, маленькая категория до конца, начало
«Весь сайт» с маленьким лимитом. У каждого сохранённого товара проверить, что
описание не пустое. Zara, FLO и akakce идут через платный прокси — не больше
3 товаров. Instagram — один пост и начало профиля с маленьким лимитом и
паузами между запросами.
