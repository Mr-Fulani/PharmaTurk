# Второй фактор входа в Django Admin

Актуально: **22 ноября 2026 года**. Библиотека — `django-otp` (коды TOTP из приложения и одноразовые
запасные коды).

## Как это работает

- У сотрудника, который включил второй фактор, форма входа `/admin/login/` после пароля требует
  **код из приложения** (6 цифр) или **запасной код** (8 знаков, работает один раз).
- У сотрудника без второго фактора вход остаётся по паролю. Чтобы требовать код у всех, на сервере
  задаётся `ADMIN_OTP_REQUIRED=1` в `.env` — **только после того, как каждый сотрудник включил код**,
  иначе он не войдёт.
- Сессия, открытая до включения второго фактора на другом устройстве, перестаёт пускать в админку:
  нужно войти заново с кодом.
- Несколько неверных кодов подряд — пауза, которая растёт с каждой ошибкой (встроено в `django-otp`).
  Сверх этого nginx ограничивает `/admin/login/` (10 запросов в минуту с адреса).
- Вход по API (JWT) второй фактор не спрашивает: он защищает только Django Admin.

## Включить второй фактор (делает каждый сотрудник сам)

1. Установите на телефон приложение для кодов: Google Authenticator, Яндекс Ключ или подобное.
2. Войдите в админку и откройте `https://mudaroba.com/admin/two-factor/` (ссылка «Второй фактор
   входа: код из приложения» внизу главной страницы админки).
3. В приложении: «Добавить аккаунт» → «Сканировать QR-код», наведите камеру на картинку на странице.
   Если камера не читает — «Ввести ключ вручную» и ключ со страницы.
4. Введите 6 цифр из приложения в поле на странице и нажмите **«Включить второй фактор»**.
5. Страница покажет **5 запасных кодов**. Сохраните их (бумага, менеджер паролей): больше они не
   показываются.

Пока верный код не введён (шаг 4), ничего не меняется — вход остаётся по паролю. Остаться без входа
на этом шаге нельзя.

## Вход после включения

`/admin/login/`: почта или логин, пароль, в поле «Код из приложения» — 6 цифр из приложения. Нет
телефона под рукой — в то же поле один из запасных кодов.

## Потерян телефон и нет запасных кодов

Сброс второго фактора у сотрудника — на сервере (после сброса он входит по паролю и включает код
заново):

```bash
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py shell -c "
from django_otp import devices_for_user
from apps.users.models import User
user = User.objects.get(email='ПОЧТА_СОТРУДНИКА')
for device in devices_for_user(user, confirmed=None):
    device.delete()
print('сброшено')
"
```

Суперпользователь может сделать то же в админке: разделы «TOTP devices» и «Static devices» —
удалить записи сотрудника.

## Код

- Форма входа с полем кода — `CustomAdminAuthenticationForm` (`backend/apps/users/admin.py`), шаблон
  `backend/templates/admin/mudaroba_login.html`.
- Проверка «сессия вошла с кодом» — `MudarobaAdminSite.has_permission`, страница включения —
  `MudarobaAdminSite.two_factor_view` (`backend/config/admin.py`), шаблон
  `backend/templates/admin/mudaroba_two_factor.html`.
- Настройки: `django_otp` в `INSTALLED_APPS`, `OTPMiddleware`, `ADMIN_OTP_REQUIRED`, `OTP_TOTP_ISSUER`
  (`backend/config/settings.py`).
- Тесты — `backend/config/tests/test_admin_two_factor.py`.
