# Посадочные страницы «Медикаментов»: подкатегории и подборки

Пункты 1 и 2 SEO-задания от 23.10.2026 (ядро запросов по Вордстату и подсказкам
Google). Корень `/categories/medicines`, 14 подкатегорий и 17 подборок получили свои
H1, title, description и SEO-текст на русском и английском, ссылки с корня и место в
sitemap.

## Адреса

Подкатегории остались по прежним адресам `/categories/<slug>`: они уже были
отдельными страницами с canonical и hreflang и стояли в sitemap. В задании
предлагалось `/categories/medicines/<slug>`, но перенос дал бы 301 у
проиндексированных адресов без выгоды. Кроме того, на всём сайте категории живут по
схеме `/categories/<slug>`. Со страницы корня на подкатегории раньше не было ссылок:
боковая панель фильтрует товары через `?filter_category_slug=…`.

Подборка живёт под своей категорией: `/categories/<категория>/<подборка>`. У подборок
корня адрес совпадает с заданием (`/categories/medicines/mazi-i-kremy`). У вложенных
подборок из адреса выпадает `medicines`, потому что сама подкатегория живёт без него:
`/categories/respiratory-ent/ot-nasmorka`.

Старые адреса с фильтром (`/categories/medicines?filter_category_id=…`) по-прежнему
`noindex, follow` с canonical на корень (`buildCatalogSeoState`). Так было и до правки.

## Как собраны подборки

Подборка — модель `CategoryCollection`. Она отбирает товары **правилом по полям
медикамента**, а не списком товаров и не набором категорий:

- список товаров устаревает при каждом парсинге;
- категории слишком крупные: «От насморка» — только часть «Дыхательной системы», а
  «Мази, кремы и гели» собраны из десятка разделов.

Правило: (код АТХ начинается с префикса **или** название содержит слово) **и** форма
из списка **и** код АТХ не из исключений. Пустая часть правила не ограничивает. Товары
берутся только из категории подборки и её потомков; товары без категории — только у
подборок корня, как и в каталоге. Код АТХ берётся из `MedicineProduct.atc_code` (по
нему же разложены подкатегории). Форма — из `dosage_form`. Название ищется без учёта
регистра; турецкие и русские слова указываются оба, потому что AI переводит названия.
Товары без формы (≈ 1 тыс. из 13 тыс.) в подборки по форме не попадают.

## Где что лежит

| Что | Где |
|---|---|
| SEO посадочной страницы | `CategoryLandingSeoMixin`: `h1`, `meta_title`, `meta_description`, `seo_text` в `CategoryTranslation` и `CategoryCollectionTranslation` (по языку) |
| Подборка и её правило | `CategoryCollection` (`apps/catalog/models.py`), миграция 0221 |
| Тексты и 17 подборок | миграция 0222: пишет только пустые поля и только новые подборки, без категории пропускает |
| API категории | `GET /api/catalog/categories/<id или slug>` (раньше slug давал 500); SEO — поле `seo`, в списке только с `include_seo=true` |
| API подборок | `GET /api/catalog/collections?root_slug=…` / `?parent_slug=…`, `GET /api/catalog/collections/<slug>` (с SEO) |
| Товары подборки | `GET /api/catalog/medicines/products?collection=<slug>`; неизвестная подборка — пустой список |
| Sitemap | `sitemap-entries?kind=collections` (только непустые) → секция `categories` |
| Страница | `pages/categories/[slug].tsx` (та же gSSP), маршрут `pages/categories/[slug]/[collection].tsx` |
| Ссылки и SEO-текст внизу | `components/CategoryLandingBlock.tsx`, разбор текста — `splitSeoText` (`lib/seoText.js`) |

Приоритет меты: перевод страницы на языке запроса (`landingSeo`) → для RU-категории
`Category.meta_title` → шаблон. У подборки без перевода — шаблон «Название — Mudaroba».
H1 — `h1` перевода, иначе название. SEO-текст — обычный текст: абзацы через пустую
строку, строка `## …` — подзаголовок H2, HTML не исполняется.

Перелинковка: на корне — «Разделы» (все подкатегории) и «Подборки» (все подборки
дерева). На подкатегории и подборке — подборки этой категории. Если подборок нет,
блок ссылок не выводится, поэтому другие типы каталога не изменились.

`collection` — параметр маршрута, а не фильтр: страница подборки индексируется и
canonical ведёт на неё саму (`INDEXABLE_CATEGORY_QUERY_KEYS`). Пустая подборка, как
и пустая категория, отдаётся с `noindex` и в sitemap не попадает.

## Как править

В админке — «Каталог → Категории и справочники»:

- **Категории — Медицина** → категория → перевод → «SEO посадочной страницы».
  Пустое поле включает шаблон.
- **Подборки категорий**: правило отбора (коды АТХ, слова, формы, исключения),
  порядок и активность. Тексты — в переводах подборки.

Миграция 0222 не перетирает поля, заполненные вручную.

## Ограничения текстов

- Нигде нет «без рецепта». Рецептурный статус — «отмечен в карточке». Флаг
  `prescription_required` сейчас стоит почти у всех лекарств, поэтому тексты на него не
  опираются.
- Не упоминаются DUROGESIC, PERGE, PAGAMAX и бренды, в линейке которых есть кодеин или
  псевдоэфедрин. По этой причине не названы A-FERIN, PAROL, TYLOLHOT, KATARIN и BROKSIN — см. TD-024.
- Соблюдены минус-слова задания. В «Уколах» D3 назван через колекальциферол, потому
  что слово «витамин» в минус-словах.
- Нет обещаний результата: «применяют при…», «назначает врач», в каждом тексте —
  призыв прочитать инструкцию и посоветоваться с врачом.
- Бренды в текстах сверены с каталогом 23.10.2026 через публичный API.

## Деплой и проверка

Полный релиз: в миграции 0221 есть новые таблицы, это не сокращённый backend-релиз.
Порядок выкладки фронтенда и бэкенда не важен. Новый фронт со старым бэком не
показывает блок подборок (`collections` → пусто), а страницы подборок отдают 404.
Старый фронт новые поля просто не читает.

После деплоя:

```bash
curl -s https://mudaroba.com/categories/medicines | grep -E '<title|<h1|canonical|hrefLang'
curl -s https://mudaroba.com/en/categories/medicines/ot-prostudy-i-grippa | grep -E '<title|canonical|robots|hrefLang'
curl -s https://mudaroba.com/sitemaps/categories.xml | grep -c '/categories/medicines/'
curl -s -o /dev/null -w '%{http_code}\n' https://mudaroba.com/api/catalog/categories/medicines
```

Число товаров в подборках на проде проверить в админке («Подборки категорий») или
запросом `…/medicines/products?collection=<slug>&page_size=1&view=card`. Если
подборка оказалась пустой или слишком широкой, поправить правило в админке.
