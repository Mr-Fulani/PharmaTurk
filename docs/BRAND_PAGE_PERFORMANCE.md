# Скорость страницы бренда (`/brand/<slug>`) — октябрь 2026

Клик по карточке бренда на главной и на `/brands` ждёт `getServerSideProps`
страницы бренда: Next.js открывает её только после ответа трёх запросов к API —
`/api/catalog/brands/<slug>`, `/products` и `/categories`.

## Замеры «до» (прод, 2026-10-20, через сайт, `curl -w`)

HTML без cookie, первый запрос (Cloudflare `MISS`); повтор через 1–2 с иногда
`HIT` (~0.23 с), но 843 бренда × 2 языка при `s-maxage=300` почти всегда холодные.

## Причины

1. **500 у всех брендов без описания.** С 2026-10-17 (`26bc8f7a`) мета-описание
   строилось как `localizedBrandDescription.replace(...)`, а у брендов без
   описания — все 783 бренда, созданные из производителей лекарств и БАДов, —
   функция возвращает `null`: SSR падал. Cloudflare кэшировал и эти 500.
2. **Детоаст `external_data`.** Витрина бренда собирает товары из 18 доменных
   таблиц; служебные строки (копии вариантов, заглушки лекарств) отсекались
   условиями `external_data ? '…'` прямо в основном запросе. Планировщик
   проверял их по каждой строке таблицы раньше `brand_id` и читал многомегабайтные
   дампы парсеров: лекарства TEB — 3.7 с (134 тыс. буферов), мебель IKEA — 1.2 с.
   Тот же запрос — в `/categories` (2.5 с у TEB).
3. **Счётчики категорий на каждый товар.** `serialize_product_for_card` создавал
   новый context на каждый товар, и батч-кэш `CategorySerializer` пересчитывал
   `GROUP BY` по всей `catalog_product` 24 раза (~1 с SQL + дерево и переводы).
4. **Аннотация счётчика в detail/products/categories.** `get_queryset` аннотировал
   `Count('products', filter=…)` через JOIN — детоаст всех товаров бренда
   (IKEA 0.5 с) на каждом из трёх запросов страницы.
5. **Полные карточки.** `/products` отдавал полные инструкции лекарств и вложенные
   бренд/категорию: 0.8 МБ на 24 лекарства, ~0.9 МБ JSON при клиентском переходе.

## Что сделано

- `pages/brand/[slug].tsx`: описание без HTML — `brandDescriptionText()` (`null` → `''`);
  три запроса gSSP идут параллельно.
- `lib/brandCatalog.js`: страница бренда запрашивает `view=card` — те же поля
  карточки, что у категорий (`compact_card_product_payload`).
- `BrandViewSet._brand_base_queryset`: служебные строки исключаются подзапросами
  `id NOT IN (…)` / `base_product_id NOT IN (…)`; основной запрос больше не
  касается `external_data`. Подзапросы читают частичные индексы миграции
  `0217` (`catalog_product_nonpublic_id_idx` — 941 строка из 26 тыс. —
  и `catalog_<домен>_source_variant_idx`). Предикаты индексов обязаны совпадать
  с `non_public_shadow_product_q()` и `source_variant_q()`
  (`apps/catalog/querysets.py`); тест — `test_brand_source_exclusions_can_use_partial_indexes`.
- `BrandViewSet.get_queryset` больше не аннотирует счётчик: detail получает точный
  `products_count` из `BrandSerializer` — COUNT по частичному индексу `0208`
  (6–24 мс), `products` ставит его сам, `categories` он не нужен.
- `/products`: один serializer context на страницу (`serialize_product_for_card(…, context=…)`);
  в `view=card` счётчики вложенных бренда/категории не считаются.
- Контракт API без `view=card` прежний (вложенный бренд с точным счётчиком).

`0217`, < 1 мс):

| ikea | 0.54 → 0.09 с | 4.3 → 1.2–1.7 с, 130 → 33 КБ | 1.42 → 0.32 с |
| lc-waikiki | 0.37 → 0.02 с | 3.6 → 1.0 с, 110 → 42 КБ | → 0.36 с |
| teb | 0.14 → 0.03 с | 5.9 → 0.6 с, 115 → 27 КБ | 2.77 → 0.30 с |

Ожидаемый TTFB холодной страницы: бренды лекарств и БАДов ~0.8–1.2 с (было 1.2–6.5 с
и 500), мебель/одежда ~1.5–2 с (было 2–4.4 с). Повтор в течение 5 минут — из
Cloudflare (~0.2 с), как у категорий; отдельное правило Cloudflare не нужно —
`/brand/*` и `/_next/data/*` уже кэшируются правилом «HTML respect origin».

## Деплой

- Полный релиз (миграция `0217`, 19 × `CREATE INDEX CONCURRENTLY`; без блокировок
  записи, дольше всех — `catalog_medicineproduct`, она читает весь TOAST ~0.4 ГБ).
  Сокращённый backend-релиз миграцию с индексами не пропустит.
- Порядок backend/frontend не важен: старый backend игнорирует `view=card`,
  старый frontend получает прежний полный ответ.
- После деплоя: `curl -w '%{time_starttransfer}'` для `/brand/teb`, `/brand/ikea`,
  `/en/brand/teb` — 200 и время из прогноза; EXPLAIN запроса витрины TEB
  должен показывать `catalog_product_nonpublic_id_idx`.

## Что осталось

- **N+1 вариантов** в доменных сериализаторах (`_get_default_variant`/`_get_active_variant`
  у мебели, одежды, обуви, парфюмерии и др. — `.filter()` мимо prefetch, ~11–13
  запросов на товар): IKEA 264, LC Waikiki 313, Puma 177 запросов, ~0.5 с на странице.
- Cloudflare кэширует ответы 500 страниц с `s-maxage` (заголовок ставится до
  ошибки рендера). Затрагивает все gSSP-страницы, не только бренды.
