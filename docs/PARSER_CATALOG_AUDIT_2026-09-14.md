# Проверка парсеров перед общим релизом — 14 сентября 2026

Ветка: `codex/fix-parser-catalog-traversal`. Изменения пока не опубликованы.

## Подготовленные исправления

- FLO: сохранённые карточки и их цвета отсеиваются до повторной загрузки;
  остаток лимита считается после обработки результата сервисом. Повторившаяся
  выдача и три последовательные страницы без новых товаров завершают обход.
- IlacFiyati: корневые каталоги и 49 текущих разделов БАДов распознаются как
  каталоги. Современный список извлекается из карточек товаров; меню категорий
  не попадает в обработку. Сохранён старый формат списков лекарств.
- IlacFiyati: защита от повторов, остановка по последней странице и корректный
  учёт остатка лимита. Фильтры URL сохраняются при переходе по `pg`.
- Пауза сохраняет время начала прохода и его пространство ключей кэша;
  новый запуск получает новое пространство и может повторно обновлять товары.
- Контрольные точки страниц записываются после завершения страницы, поэтому
  пауза или soft timeout не препятствуют дочитыванию незавершённой страницы.

Для распознавания URL БАДов используется список текущих категорий источника:
категория и товар имеют одинаковую структуру `/takviye-edici-gida/<slug>`.
При добавлении источником новых категорий этот список нужно актуализировать.

### Pull&Bear, Bershka, Massimo Dutti

Сохранённые ошибки задач [79](https://mudaroba.com/admin/scrapers/sitescrapertask/79/change/),

Задачи относятся к прямым ссылкам на товары, а не каталогам.

Все три страницы открылись в обычном браузере при текущей проверке. Это не
доказывает доступность их HTTP-интерфейсов из серверного окружения.

Дополнительная проверка из локального Docker через `curl_cffi` с
`impersonate="chrome"` вернула HTTP 200 для всех трёх прямых ссылок. Тела
ответов размером около 2,4–2,5 КБ содержат проверку Akamai (`bm-verify`,
`/_sec/verify`), а не товарные данные. Такой ответ не считается успешным
парсингом. Параметры доступа к production для серверной проверки запрошены.

В текущем общем адаптере ожидается формат Zara `viewPayload`. На проверенных
страницах обнаружены другие форматы:

| Источник | Наблюдаемый формат |
| --- | --- |
| Pull&Bear | Конфигурация `inditex` и JSON-LD Product; ожидаемый `viewPayload` отсутствует |
| Bershka | Сериализованное состояние `window.__NUXT__` и JSON-LD Product |
| Massimo Dutti | JSON `mdfrontw-state`, ключ `ITX_GET_PRODUCT_DETAIL_KEY`, и JSON-LD ProductGroup |

Адаптация этих источников и проверка доступа с сервера пока не выполнены.
Имеющиеся тесты sibling-парсеров используют пример payload Zara; их успешное
прохождение не подтверждает совместимость с перечисленными живыми форматами.

Дополнительно при просмотре кода обнаружена ошибка извлечения категорий этих
трёх парсеров: `InditexSiblingParser.CATEGORY_PATH_RE` не содержит группы захвата,
а унаследованный `_extract_category_links` вызывает `match.group(1)`. Этот путь
нуждается в исправлении и отдельной регрессионной проверке.
