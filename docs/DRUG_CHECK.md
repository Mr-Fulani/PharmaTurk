# Проверка лекарства по нескольким источникам (TD-044)

Актуально на 20.11.2026 (шаги 1–2 на проде с выпуска 4ddd8f86; заметная проверка и ручные действия — PR #421; ссылки на проверку и итог простыми словами в сообщении о заявке — 20.11). Код — `backend/apps/drug_check/`. Подход одобрен владельцем 10.11.2026.

## Зачем

По заявке или вопросу клиента менеджеру нужны свежие цена и «продаётся ли» конкретного
препарата. Статус «Aktif» на IlacFiyati этого не показывает: NEXIUM 40 мг 14 таб. и CRESTOR
5 мг 28 таб. там «Aktif» с ценой, а государственный список SKRS выключил их в 2025 году.

**Проверка только показывает.** Цены, наличие и видимость товаров на сайте она не меняет и не
скрывает (решение владельца 12.11.2026: 1 454 «пассивных» лекарства остаются в продаже — мы
проверяем не все источники, менеджер ищет препарат сам, когда приходит заказ).

## Источники

| Источник | Что даёт | Как работает | Модуль |
|---|---|---|---|
| **SKRS E-Reçete (TİTCK)** | «Активен с …» / «Пассивен с …», для свежих — причина («по данным İTS нет на рынке») | открытый файл раз в неделю (выходит по вторникам), проверка по штрихкоду в своей таблице, без запросов наружу | `sources/skrs.py` |
| **IlacFiyati** | цена сейчас, дата изменения цены («Fiyat Geçerlilik Tarihi»), «Aktif / Pasif», штрихкод на странице | карточка из нашей записи — 1 запрос; без карточки — поиск по штрихкоду и карточка — 2 запроса; без прокси, без повторов, без вкладок инструкции и аналогов | `sources/ilacfiyati.py` |
| **Прайс склада Selçuk Ecza** | цена склада с датой, «не производится», «нет у склада» | открытый файл `WEBLISTE-ДД-ММ-ГГГГ.xlsx` раз в неделю, проверка в своей таблице | `sources/selcuk.py` |

Новый источник — модуль в `sources/` с `key`, `title` и `check(ctx) -> SourceResult` и строка в
`SOURCES` (`sources/__init__.py`). Источник-файл наследует `FileSource` (скачивание, замена строк,
журнал загрузок уже есть) и описывает только ссылку на файл (`find_file_url`), разбор (`parse`) и
вывод (`describe`). Excel читается своим модулем `xlsx.py` (zipfile + ElementTree) — новой
зависимости в образе нет.

Не используются (решения TD-044): закрытые разделы (Web Depo склада, ITS, портал TİTCK со
входом), прокси, массовый обход сайтов. ilacrehberi / ilacdata автоматически не подключаются
(robots запрещает `/api/`): в окне проверки есть только ссылка для ручного просмотра менеджером.
Склад на витрине не называется — его имя видно только в админке и в сообщении менеджеру.

## Как читать результат

| Цвет | Значение | Примеры |
|---|---|---|
| красный | расхождение | у нас «в наличии», а SKRS «пассивен»; цена IlacFiyati или склада другая (больше 5 курушей); на странице IlacFiyati «Pasif» или другой штрихкод |
| жёлтый | подсказка — проверить | «нет у склада» (склад возит ~6 тыс. позиций из ~12 тыс. наших), «не производится» у склада, у нас «нет в наличии», а в SKRS активен; нет в списке SKRS |
| серый | проверить не удалось | источник не ответил, время вышло, файл ещё не загружен, нет настоящего штрихкода (служебный `1111111…`) |
| зелёный | источник согласен с нами | |

Если у нас карточки нет (проверка по штрихкоду), «пассивен» и «нет у склада» — сведения, не
расхождения: сравнивать не с чем.

## Где в админке

С 18.11.2026 проверка вынесена на видные места (владелец не нашёл маленькую кнопку в блоке
«Специфика медикамента»):

- **Главная админки** — первым блоком над списком разделов поле **«Проверить лекарство: продаётся ли
  и какая цена»**: название (от 3 букв) или штрихкод → «Проверить». Работает и для препаратов,
  которых нет на сайте. Тот же поиск — пункт меню **«Проверка лекарств» → «Проверить лекарство
  (название или штрихкод)»** (группа стоит сразу после «Товаров каталога»).
- **Карточка лекарства** — в самом верху формы, над полями, панель **«Наличие и цена: проверка по
  источникам»**: наша цена и наличие, строки SKRS и склада по своим спискам (открывается мгновенно, без
  запросов наружу), рамка панели красная / жёлтая / зелёная по худшему итогу, крупная кнопка
  **«Проверить сейчас»**. Из заказа сюда ведёт кнопка «Карточка в админке» у позиции-лекарства
  (`docs/ORDER_PROCESSING.md`).
- **Список лекарств** — в каждой строке кнопка **«Проверить»** (вторая колонка).
- **Окно проверки** (открывается в новой вкладке, 1–3 секунды) — наша цена и наличие, строки SKRS,
  IlacFiyati (цена на сегодня), склада, дата файлов и блок **«Что сделать»** (см. ниже).
- Поиск по названию находит у нас по тому же поиску, что сайт, и в списках SKRS и склада без запросов
  наружу; у найденного — ссылка на проверку. Штрихкод — полная проверка (если у нас есть карточка с
  этим штрихкодом — по ней).
- **«Загрузки справочных файлов»** — журнал: какой файл, от какой даты, сколько строк, ошибки.

Проверка — с правом просмотра лекарств (`catalog.view_medicineproduct`), действия — с правом их
изменения (`catalog.change_medicineproduct`).

## Ручные действия: принять цену, сменить наличие (TD-044, шаг 3)

В окне проверки, блок «Что сделать» (только с правом изменения лекарств):

- **«Принять цену X TL (IlacFiyati, цена от …)»** — если цена IlacFiyati отличается от нашей. Цена
  берётся из этой же проверки (подписанная запись, действует час; повторного запроса к источнику нет,
  подделать цену в форме нельзя). Больничным препаратам (`is_hospital`) цена предлагается так же,
  как обычным: с 19.11.2026 цену не скрываем. Цену склада не принимаем: у склада свой прайс, база цены сайта — IlacFiyati, склад
  показывается для сведения.
- **«Отметить: нет в наличии» / «Отметить: в наличии»** — показывается кнопка, противоположная
  текущему состоянию, с подсказкой, что говорят источники. Видимость товара (`is_active`) не меняется.
- Каждое действие: страница подтверждения «было → станет» (GET ничего не меняет) → кнопка
  подтверждения (POST с CSRF). Запись — через `MedicineProduct.save()` (синхронизирует `Product`, тот
  пересчитывает цены в рублях и других валютах), как при правке в админке и проверке цены на витрине.
  Прежняя цена не становится «старой ценой со скидкой» (`old_price` очищается); новая цена пишется в
  историю цен (`PriceHistory`, источник `drug_check_manual`). В журнал админки (история карточки)
  пишется кто, когда, «было → стало» и источник.
- Парсер IlacFiyati при следующем обходе снова ставит цену и наличие по источнику (кроме «Pasif»):
  ручная отметка «нет в наличии» у препарата, который на IlacFiyati «Aktif», продержится до обхода.
- Массовых кнопок и автоматики нет: ничего не меняется без нажатия человека.

## Проверка при заявке

`notify_new_order_telegram` перед отправкой менеджеру проверяет лекарства заявки
(`service.order_checks`) и под каждой позицией-лекарством пишет итог и две ссылки в админку
(с 20.11.2026; раньше итог шёл отдельным блоком в конце, без ссылок):

```
1. NEXIUM (эзомепразол) 40 мг, 14 таб.
1 шт. · 1 450.00 RUB
⚠️ В реестре Турции: снят с продажи с 15.04.2025 · Цена продавца 202,15 TL — у нас в базе та же · У оптовика нет в прайсе
🔎 Проверить по источникам · Поиск по штрихкоду
```

Итог написан простыми словами и без названий источников (с 20.11.2026; `DrugCheckReport.telegram_status`):
сначала фраза про реестр (SKRS), потом одна фраза про цену, потом замечания. Подсказки в админке
(`SourceResult.short`) остались прежними, с названиями источников.

| Что нашли | Что в сообщении |
| --- | --- |
| SKRS: активен | «В реестре Турции: действует» |
| SKRS: активен, но в списке на перевод в пассивные | «В реестре Турции: действует, но в списке на снятие с продажи» |
| SKRS: пассивен с даты (с причиной) | «В реестре Турции: снят с продажи с 15.04.2025 (по данным İTS нет на рынке)» |
| SKRS: нет в списке | «В реестре Турции не найден» |
| нет настоящего штрихкода / список не загружен / сбой | «Реестр Турции: не проверить без штрихкода» / «…: список ещё не загружен» / «…: проверить не удалось» |
| цена источника равна нашей (до 5 курушей) | «Цена продавца 204,49 TL — у нас в базе та же» |
| цена источника другая | «Цена продавца выросла: 230,00 TL, у нас в базе 204,49 TL» (или «снизилась») |
| IlacFiyati и склад дают разные цены | одна фраза — про ту цену, что дальше от нашей; источники не называются |
| цену сравнить не с чем (у нас нет цены или валюта не TRY) | «Цена продавца 202,15 TL — с ценой в базе не сравнить» |
| IlacFiyati: цены нет | «У продавца цена не указана» |
| IlacFiyati не проверен | «Цену у продавца проверить не успели» / «Цену у продавца проверить не удалось: <причина>» |
| IlacFiyati: Pasif | «У продавца помечен снятым с продажи» |
| IlacFiyati: на странице другой штрихкод | «На странице продавца другой штрихкод» |
| у склада нет / «не производится» | «У оптовика нет в прайсе» / «У оптовика помечен «не производится»» |

Фразы «данных нет» у источника цены не показываются, если цену дал другой источник (IlacFiyati не
успел ответить, а в прайсе склада цена есть — в сообщении только фраза про цену). Значок: ⚠️ —
есть расхождение или подсказка (как подсветка в окне проверки), ℹ️ — расхождений нет, но каких-то
данных нет, ✅ — всё сошлось, ❔ — не ответил ни один источник.

- «Проверить по источникам» открывает окно проверки этого препарата (`drug_check_medicine`).
  «Поиск по штрихкоду» / «Поиск по названию» открывает окно поиска (`drug_check_lookup`) с уже
  заполненным полем: `…/lookup/?q=<значение>` — настоящий штрихкод, иначе турецкое название
  источника (`service.lookup_query`). Окно ищет в нашем каталоге и в списках SKRS и склада; по
  штрихкоду — полная проверка. Вход в админку обязателен, токенов в ссылке нет.
- В заявке «Найдём товар» — ссылка на то же окно поиска с текстом покупателя в поле.
- Проверка, как и раньше, на сайте ничего не меняет.
- Заявка создаётся сразу: уведомление и так идёт фоновой задачей Celery. На все лекарства
  заявки — не больше 15 секунд (`ORDER_CHECK_SECONDS`); что не успели — «Цену у продавца проверить
  не успели», фраза про реестр есть всегда (своя таблица).
- Не больше 10 препаратов (`ORDER_MAX_MEDICINES`), у остальных — только ссылки на проверку.
- Итог считается один раз: повтор задачи после сбоя Telegram получает те же итоги
  (`drug_checks`) и не ходит в источники снова.
- Ошибка проверки не мешает уведомлению: строка «❔ Проверить не удалось» или, если не удалось
  прочитать позиции заявки, без итогов проверки.
- Покупателю и в PDF-чек проверка не попадает.
- Товар, перенесённый из БАДов в лекарства (`external_data["moved_from_supplements"]`,
  команда `move_supplements_to_medicines` — глазные капли, назальные спреи, пластыри), не
  проверяется: в SKRS и у склада его нет, «нет в списке» было бы ложной тревогой. Ссылки на
  ручную проверку под позицией остаются.

## Загрузка файлов

Задача `drug_check.load_reference_files` — по средам в 10:20 МСК (`CELERY_BEAT_SCHEDULE`
`drug-check-load-reference-files`). Для каждого источника: страница источника → ссылка на самый
свежий файл → если имя файла то же, что у прошлой удачной загрузки, файл не качается («Тот же
файл») → иначе файл в память (не больше 25 МБ, только с домена источника, без прокси), разбор,
замена строк источника одной транзакцией. На диск файл не пишется. Ошибка — строка «Ошибка» в
журнале, прежние строки остаются.

Причина перевода в пассивные есть только в листе изменений той недели; при следующих загрузках
она сохраняется, пока у препарата тот же статус и дата.

Ручной запуск:

```bash
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py load_drug_reference_files
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py load_drug_reference_files --source skrs --force
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py load_drug_reference_files --source selcuk --file /tmp/WEBLISTE-13-10-2026.xlsx
```

`--file` — если сайт источника недоступен с сервера, а файл скачан вручную (путь внутри контейнера, `docker cp`); дата берётся из имени.

Размер: SKRS ~18 тыс. строк, склад ~6,3 тыс., таблица — единицы МБ. Таблица восстанавливается
повторной загрузкой, в `REQUIRED_TABLES` бэкапа она не входит.
