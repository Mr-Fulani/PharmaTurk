# Проверка лекарства по нескольким источникам (TD-044)

Актуально на 13.11.2026. Код — `backend/apps/drug_check/`. Подход одобрен владельцем 10.11.2026.

## Зачем

По заявке или вопросу клиента менеджеру нужны свежие цена и «продаётся ли» конкретного
препарата. Статус «Aktif» на IlacFiyati этого не показывает: NEXIUM 40 мг 14 таб. и CRESTOR
5 мг 28 таб. там «Aktif» с ценой, а государственный список SKRS выключил их в 2025 году.

**Проверка только показывает.** Цены, наличие и видимость товаров на сайте она не меняет и не
скрывает (решение владельца 12.11.2026: 1 454 «пассивных» лекарства остаются в продаже — мы
проверяем не все источники, менеджер ищет препарат сам, когда приходит заказ).

## Источники

| Источник | Что даёт | Как работает | Модуль |
|---|---|---|---|
| **SKRS E-Reçete (TİTCK)** | «Активен с …» / «Пассивен с …», для свежих — причина («по данным İTS нет на рынке») | открытый файл раз в неделю (выходит по вторникам), проверка по штрихкоду в своей таблице, без запросов наружу | `sources/skrs.py` |
| **IlacFiyati** | цена сейчас, дата изменения цены («Fiyat Geçerlilik Tarihi»), «Aktif / Pasif», штрихкод на странице | карточка из нашей записи — 1 запрос; без карточки — поиск по штрихкоду и карточка — 2 запроса; без прокси, без повторов, без вкладок инструкции и аналогов | `sources/ilacfiyati.py` |
| **Прайс склада Selçuk Ecza** | цена склада с датой, «не производится», «нет у склада» | открытый файл `WEBLISTE-ДД-ММ-ГГГГ.xlsx` раз в неделю, проверка в своей таблице | `sources/selcuk.py` |

Новый источник — модуль в `sources/` с `key`, `title` и `check(ctx) -> SourceResult` и строка в
`SOURCES` (`sources/__init__.py`). Источник-файл наследует `FileSource` (скачивание, замена строк,
журнал загрузок уже есть) и описывает только ссылку на файл (`find_file_url`), разбор (`parse`) и
вывод (`describe`). Excel читается своим модулем `xlsx.py` (zipfile + ElementTree) — новой
зависимости в образе нет.

Не используются (решения TD-044): закрытые разделы (Web Depo склада, ITS, портал TİTCK со
входом), прокси, массовый обход сайтов. ilacrehberi / ilacdata автоматически не подключаются
(robots запрещает `/api/`): в окне проверки есть только ссылка для ручного просмотра менеджером.
Склад на витрине не называется — его имя видно только в админке и в сообщении менеджеру.

## Как читать результат

| Цвет | Значение | Примеры |
|---|---|---|
| красный | расхождение | у нас «в наличии», а SKRS «пассивен»; цена IlacFiyati или склада другая (больше 5 курушей); на странице IlacFiyati «Pasif» или другой штрихкод |
| жёлтый | подсказка — проверить | «нет у склада» (склад возит ~6 тыс. позиций из ~12 тыс. наших), «не производится» у склада, у нас «нет в наличии», а в SKRS активен; нет в списке SKRS |
| серый | проверить не удалось | источник не ответил, время вышло, файл ещё не загружен, нет настоящего штрихкода (служебный `1111111…`) |
| зелёный | источник согласен с нами | |

Если у нас карточки нет (проверка по штрихкоду), «пассивен» и «нет у склада» — сведения, не
расхождения: сравнивать не с чем.

## Где в админке

- **Карточка лекарства** → «Специфика медикамента» → **«Проверить сейчас»** (открывается в новой
  вкладке, 1–3 секунды): наша цена и наличие, строки SKRS, IlacFiyati, склада, дата файлов.
- **«Проверка лекарств» → «Справочные списки» → «Проверить по названию или штрихкоду»**
  (`/admin/drug_check/drugreferenceentry/lookup/`): штрихкод — полная проверка (если у нас есть
  карточка с этим штрихкодом — по ней); название (от 3 букв) — поиск в нашем каталоге и в списках
  SKRS и склада без запросов наружу, у найденного — ссылка на проверку.
- **«Загрузки справочных файлов»** — журнал: какой файл, от какой даты, сколько строк, ошибки.

Нужно право просмотра лекарств (`catalog.view_medicineproduct`).

## Проверка при заявке

`notify_new_order_telegram` перед отправкой менеджеру проверяет лекарства заявки
(`service.order_check_text`) и дописывает в конец сообщения по строке на препарат:

```
🔎 Проверка лекарств (на сайте ничего не меняется):
• NEXIUM (эзомепразол) 40 мг, 14 таб.: ⚠️ SKRS: пассивен с 15.04.2025; IlacFiyati 202,15 TL (= наша); у склада нет
```

- Заявка создаётся сразу: уведомление и так идёт фоновой задачей Celery. На все лекарства
  заявки — не больше 15 секунд (`ORDER_CHECK_SECONDS`); что не успели — «IlacFiyati: не успели
  проверить», строки SKRS и склада есть всегда (своя таблица).
- Не больше 10 препаратов (`ORDER_MAX_MEDICINES`), остальные — «проверьте в админке».
- Итог считается один раз: повтор задачи после сбоя Telegram получает тот же текст
  (`drug_check_text`) и не ходит в источники снова.
- Ошибка проверки не мешает уведомлению: строка «❔ не удалось проверить» или, если не удалось
  прочитать позиции заявки, без блока проверки.
- Покупателю и в PDF-чек проверка не попадает.

## Загрузка файлов

Задача `drug_check.load_reference_files` — по средам в 10:20 МСК (`CELERY_BEAT_SCHEDULE`
`drug-check-load-reference-files`). Для каждого источника: страница источника → ссылка на самый
свежий файл → если имя файла то же, что у прошлой удачной загрузки, файл не качается («Тот же
файл») → иначе файл в память (не больше 25 МБ, только с домена источника, без прокси), разбор,
замена строк источника одной транзакцией. На диск файл не пишется. Ошибка — строка «Ошибка» в
журнале, прежние строки остаются.

Причина перевода в пассивные есть только в листе изменений той недели; при следующих загрузках
она сохраняется, пока у препарата тот же статус и дата.

Ручной запуск:

```bash
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py load_drug_reference_files
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py load_drug_reference_files --source skrs --force
docker exec mudaroba-backend-1 /app/.venv/bin/python manage.py load_drug_reference_files --source selcuk --file /tmp/WEBLISTE-13-10-2026.xlsx
```

`--file` — если сайт источника недоступен с сервера, а файл скачан вручную (путь внутри контейнера, `docker cp`); дата берётся из имени.

Размер: SKRS ~18 тыс. строк, склад ~6,3 тыс., таблица — единицы МБ. Таблица восстанавливается
повторной загрузкой, в `REQUIRED_TABLES` бэкапа она не входит.
