# Категории медикаментов в парсере

## Контракт

- Подкатегория задачи → категория задачи → категория конфигурации.
  Явная подкатегория задачи остаётся авторитетной. Подкатегория конфигурации
  сохраняет прежний режим: дозаполнение, а не замена ручной категории.
- Для IlacFiyati общий корень `medicines` больше не сбрасывает существующую
  подкатегорию, в том числе при выключенном флаге автоматизации.
- `MEDICINE_CATEGORY_AUTOMATION_ENABLED=true` разрешает уточнить корень/NULL
  по свежему ATC и штрихкоду. Название/описание не используются для догадок.
  Назначается только существующая активная категория непосредственно под корнем.
- Сравниваются заполненные штрихкоды, ATC и действующие вещества из свежего
  ответа, доменной карточки и обоих JSON-снимков. Конфликт, другой тип товара
  в medicine-контексте или данные варианта → пропуск всей карточки.
  Причина пишется в `ScrapedProductLog.message`. Медиа и source offers такого
  товара не обновляются. Пустые значения не считаются инструкцией удалить данные.
- Исключение с 10.11.2026: расходится только ATC или вещество (`atc_code_conflict`,
  `active_ingredient_conflict`), а настоящий штрихкод источника совпал со штрихкодом
  карточки — упаковка та же. Тогда обновляются только цена (с валютой и зачёркнутой
  ценой), наличие, остаток и служебные отметки (`last_synced_at`, `scraped_sources`,
  предложение источника); категория, название, описание, бренд, атрибуты, фото и
  аналоги не меняются. В логе: «Товар updated; обновлены только цена и наличие: …
  (atc_code_conflict)». Без штрихкода у источника или в карточке, со служебным
  штрихкодом «1111111…», при `barcode_conflict` и `variant_or_product_type_conflict` —
  по-прежнему полный пропуск. Подробно — раздел «Чужой код АТХ» ниже.
- Неполные/неоднозначные/устаревшие ATC не дают новой категории. Неизвестная
  существующая NULL-категория остаётся NULL, без незаметного изменения наценки.
  Уже назначенные категории не переоцениваются по ATC автоматически.
- Базовая и доменная записи блокируются и сохраняются в одной транзакции;
  повторно читаются перед решением, чтобы сохранить уже завершённую ручную правку.
  Конфликт двух разных конкретных категорий требует ручной сверки.
- Каждый аналог (Eşdeğeri / SGK Eşdeğeri) сохраняется в своей точке сохранения внутри
  этой транзакции: ошибка одного аналога пишется в лог и `analog_errors`, а карточка
  и остальные аналоги сохраняются. До 04.11.2026 такая ошибка молча откатывала всю
  карточку (NUROFEN COLD & FLU и ещё 4 не обновлялись с 24–26.10).
- Штрихкод или ссылку, которые уже занимает другая строка аналогов того же товара
  (источник переставил штрихкоды двух упаковок IBUCOLD), парсер не переносит и строку
  по ним не перепривязывает: предупреждение в лог, прежняя строка остаётся как есть.
- Пустые поля и неполные словари разделов не затирают старые данные.
  Подтверждённые непустые изменения цены/наличия/описания сохраняются по прежним
  правилам. Отсутствующее количество не заменяется выдуманным остатком.

## Справочник

`apps/catalog/medicine_taxonomy.py` — единый плоский список 16 навигационных
групп для seed и классификатора. Это не лечебные рекомендации и не утверждение
о единственном показании препарата. Старые коды, переносимые между группами,
отправляются на проверку, сами ATC-коды не переписываются.

Источник проверки изменений ATC (2026-09-09):
https://atcddd.fhi.no/atc_ddd_alterations__cumulative/atc_alterations/

`seed_catalog_data --medicines-only` приводит только справочник медикаментов
к этому списку. Не меняет товары, наценки и другие разделы. Не удаляет категории;
скрывает только известные пустые устаревшие узлы без пользовательских потомков.
Наличие товаров проверяется во всех доменных моделях, а не только Product.
Seed не запускается автоматически при старте приложения.

## Проверка и включение

Тесты выполняются только на отдельной локальной базе:

```sh
pytest -q apps/scrapers apps/catalog/tests/test_medicine_taxonomy.py \
  apps/catalog/tests/test_seed_medicine_categories.py \
  apps/catalog/tests/test_product_markup_inheritance.py \
  apps/catalog/tests/test_public_price_consistency.py
```

Регрессии проверяют полный путь HTML → parser → сервис → Product/MedicineProduct,
повторный проход, сохранность галереи и переводов, отсутствие скачиваний и offer
записей при конфликте, откат при ошибке доменного сохранения, приоритет задачи.

Включение — только после CI и штатного релиза. На продакшене до этого основной
парсер остаётся на паузе. Первый запуск должен быть ограниченным, со снимками
до/после и проверкой цены, категории, атрибутов, медиа и повторного прохода.
Назначение категории существующему товару без категории может повысить его
эффективную наценку; такие изменения требуют заранее согласованной области.

Для отключения новых назначений поставить флаг в `false` и перезапустить workers
штатным процессом. Уже назначенные категории сохраняются. Для полного отката
кода использовать предыдущий релиз, но старый parser до исправления не запускать:
он может вновь сбросить подкатегории в корень.

## Чужой код АТХ в карточке (10.11.2026)

**Что было.** С 20.10.2026 парсер пропустил 1 133 лекарства: `atc_code_conflict` 640,
`variant_or_product_type_conflict` 302, `active_ingredient_conflict` 204, `barcode_conflict` 3.
У пропущенных не обновлялись ни цена, ни наличие (`last_synced_at` — начало сентября):
371 стояли «нет в наличии», 609 продавались по старой цене.

**Причина** (найдена по коду; на проде сверить выборочно: чужой код в поле должен совпасть
с кодом препарата, у которого эта карточка записана аналогом). Лекарство, впервые встреченное в списке аналогов (Eşdeğeri / SGK Eşdeğeri),
заводится заглушкой и получает ATC и вещество **родительского** препарата
(`_process_medicine_analogs`). У аналога с другой формой свой код: у таблеток BRUFEN —
M01AE01, а в поле стоял M02AA13 (код наружных форм того же вещества). Когда парсер позже читал полную карточку заглушки,
верный код попадал в `external_data.attributes` товара и медикамента, но поле
`MedicineProduct.atc_code` не менялось: `_update_medicine_attributes` заполняет только
пустые поля. Со следующего прохода сверка идентичности (с 09.09.2026) видела расхождение
и пропускала карточку. С веществом то же самое: в поле осталась запись родителя
(«amoksisilin»), в источнике своя («Amoksisilin trihidrat»).

**Что исправлено в коде.**

- Заглушка, ставшая полной карточкой, получает ATC и вещество из своей страницы
  (`_replace_stub_inherited_identity`) — новых расхождений не появляется.
- Готовой (не заглушке) карточке аналога ATC и вещество родителя больше не пишутся.
- Уже расходящиеся карточки получают цену и наличие (исключение в «Контракте»).

**Починка накопленного — `repair_medicine_atc_codes`.** Ставит поле `atc_code` по коду
источника там, где он одинаков в `external_data.attributes.atc_code` товара и медикамента
и отличается от поля. Заглушки, пустое поле и случаи, где две копии не совпали, не трогает.
Пишет только `atc_code` через `update()` (без сигналов), в сеть не ходит.

```bash
manage.py repair_medicine_atc_codes                       # показ: сколько и примеры «было → станет»
manage.py repair_medicine_atc_codes --apply --backup /backups/medicine-atc-YYYYMMDD.json
manage.py repair_medicine_atc_codes --restore /backups/medicine-atc-YYYYMMDD.json   # откат
```

`--restore` возвращает код, только если его не меняли после починки. Существующий файл
`--backup` не перезаписывается.

**Что изменится после починки, кроме поля.**

- Категория, название, описание и SEO товара командой не меняются.
- Подборки категорий с правилом по началу кода АТХ (`CategoryCollection.atc_prefixes`)
  считаются по полю на лету: товар уйдёт из чужой подборки и появится в своей (например,
  крем с кодом назального средства R01 — в кожные D07). Блок аналогов по ATC (`medicine_reference`) тоже
  начнёт подбирать препараты своей формы.
- Со следующего прохода парсер снова обновляет такую карточку целиком, по обычным правилам:
  описание источника (если тексты не принадлежат AI), атрибуты, фото. Категорию он уточняет
  только у товара в корне «Медицина» или без категории и только при
  `MEDICINE_CATEGORY_AUTOMATION_ENABLED=true`; уже назначенную не переоценивает.
- Поиск по коду АТХ на сайте увидит новый код после `rebuild_product_search_index --apply`
  (запись идёт через `update()`).

**Что не починено.**

- `active_ingredient_conflict` (204): поле вещества автоматически не правится — в нём может
  быть и запись родителя, и ручная правка, а написания у источника разные (соль, регистр,
  порядок в комбинациях). Цена и наличие у таких карточек теперь обновляются; сверка
  содержимого — отдельная задача (TD-045).
- `variant_or_product_type_conflict` (302): код не менялся, разбор — TD-045.
