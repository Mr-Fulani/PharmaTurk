# Обработка заявок в админке

Состояние на 08.11.2026. Код — `backend/apps/orders/processing.py`, `OrderAdmin` в
`backend/apps/orders/admin.py`, модели `Order.processing_status`, `Order.assigned_to`,
`OrderProcessingEvent`; тесты — `backend/apps/orders/tests/test_order_processing.py`.

Оплата на сайте выключена, заказ — это заявка менеджеру. Чтобы через неделю было видно,
на какие заявки уже ответили и кто, у заказа есть отметка «Обработка» и ответственный.

## Отметка «Обработка» и «Статус для клиента» — разные вещи

| | «Обработка» | «Статус для клиента» |
| --- | --- | --- |
| Для кого | менеджеры | клиент |
| Видит клиент | нет | да, в профиле |
| Сообщение клиенту при смене | нет | да, Telegram/email (`notify_order_status_changed`) |

Значения «Обработки»:

| Значение | Когда ставить |
| --- | --- |
| Новая | заявка пришла, никто не смотрел (у каждой новой заявки) |
| В работе | менеджер взял заявку и уточняет наличие, цену, доставку |
| Ответили клиенту — ждём | клиенту написали, ждём его ответа |
| Обработана | вопрос закрыт: заказ оформлен или клиент получил ответ |
| Отменена | клиент передумал, дубль, спам |

## Как работать (админка → «🛒 Заказы — Заказы»)

- Список сверху вниз: «Новая», «В работе», «Ответили клиенту — ждём», потом закрытые;
  внутри — сначала свежие. Клик по заголовку колонки меняет сортировку.
- Колонки «Обработка» (цветная метка) и «Ответственный» (по имени из профиля, иначе email).
  Клиентское поле подписано «Статус для клиента», чтобы не путать с «Обработкой».
- Фильтры справа: «обработка» (плюс «Не закрытые» — новые, в работе и ждём) и
  «ответственный» («Мои», «Без ответственного», по имени).
- Действия над отмеченными галочкой заявками: «Взять в работу (я ответственный)»,
  «Отметить: ответили клиенту — ждём», «Отметить обработанной». «Отменена» и смена
  ответственного — на странице заявки, блок «Обработка заявки».
- Если заявку двигают дальше «Новой», а ответственного нет, им становится тот, кто двигает.
  «Взять в работу» всегда делает ответственным нажавшего, даже если заявку вёл другой.
- «История обработки» на странице заявки: дата, кто менял, что было → что стало,
  смена ответственного. Пишется при каждом изменении из списка и со страницы, и при
  создании заказа в админке не «Новым»; повтор того же значения не пишется.
- Страница заявки сохраняет «Обработку» и «Ответственного», только если их меняли на ней:
  если страница была открыта, пока коллега нажал «Взять в работу» в списке, сохранение
  комментария или клиентского статуса его отметку не откатит.
- Ответственным можно выбрать сотрудника (доступ в админку). Если у ответственного доступ
  сняли, он остаётся в списке у своих заявок, чтобы их можно было сохранить.
- Действия списком доступны только с правом на изменение заказов.

## Выкатка

Миграция `orders/0020_order_processing` без сети: только база. Существующие заявки
размечаются так: клиентский статус «Отменен» → «Отменена»; «Отправлен»/«Доставлен» →
«Обработана»; «Ожидает оплаты»/«Оплачен»/«В обработке» → «В работе» (без ответственного);
созданные больше 7 дней назад → «Обработана»; остальные остаются «Новая».
Истории у них нет — она начинается с первого изменения после выкатки.
