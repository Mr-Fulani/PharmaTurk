# План: парсер SuperStep Турция (superstep.com.tr)

Дата: 04.11.2026. Это **план**, код не писался, на прод ничего не записывалось.
Сайт изучен несколькими ручными запросами (около 25 запросов с компьютера и 3 запроса
с сервера прода), прокси Bright Data не тратился.

---

## 1. Коротко

- **Защиты нет.** SuperStep работает на турецкой платформе **Akinon** (сайт на Next.js,
  сервер nginx). Cloudflare-проверки, капчи и блокировки нет ни с компьютера, ни с IP
  нашего сервера. Картинки отдаются через Cloudflare CDN тоже без проверки.
- **Есть готовый JSON.** Если к любой странице сайта дописать `?format=json`, сайт
  отдаёт данные в виде JSON — без браузера и без разбора HTML:
  - страница раздела → 48 товаров с ценой, старой ценой, фото, описанием, цветами и
    размерами (есть/нет);
  - страница товара → то же плюс **точный остаток по каждому размеру** (например,
    размер 41 — 1 шт., размер 43 — 49 шт.).
- **Прокси не нужен.** Всё делаем обычным бесплатным HTTP-клиентом, как у LC Waikiki.
  Bright Data для SuperStep не нужен вообще.
- **Каталог большой:** около **15 тыс. моделей**, 90 брендов (Nike, adidas, Lacoste,
  New Balance, Converse, Puma, Nautica, Tommy Hilfiger, Calvin Klein, Skechers, Vans,
  On, Salomon, Hoka, UGG и др.).
- **Обход быстрый:** весь каталог по спискам — около 330 запросов и ~60 МБ трафика,
  15–20 минут. Открывать каждую карточку не обязательно.
- **Стоимость:** парсинг — 0 $ (без прокси). AI-карточки через Claude — порядка
  0,2–0,3 $ на 1 000 товаров (по опыту FLO), то есть ~3–5 $ на весь каталог. Картинки в
  R2 — копейки в месяц.
- **Срок:** 6 PR (последний — по необходимости), примерно 2 недели работы с пилотами.

### Решения владельца (04.11.2026)

| Вопрос | Решение |
| --- | --- |
| Что берём | **весь каталог**, если товар можно правильно разложить по нашим категориям; что разложить нельзя — не загружаем, а показываем списком (раздел 5.1); фигурки Funko/Bearbrick и шахматы — не загружаем |
| Цена | **цена витрины**; скидку «в корзине» SuperStep видит только менеджер |
| Наценка | **текущие** наценки разделов (бренд → категория → общая), своей для SuperStep нет |
| Одинаковые товары у FLO и SuperStep | показываем **одно предложение — более дорогое**; если у дорогого нет наличия, а у дешёвого есть — показываем дешёвое (раздел 7.1) |
| Проверка при добавлении в Список заявки | **как у всех**: при открытии карточки и при открытии Списка |
| Точный остаток («осталась 1 пара») | **не нужен**; наличие — «есть/нет», как у FLO |

## 2. Что за сайт (исследование)

### 2.1 Платформа и защита

| Что проверено | Результат |
| --- | --- |
| Сервер | nginx, заголовки `pz-*`, `x-middleware-rewrite` на `superstep.api.akinoncloud.com` → платформа Akinon (ProjectZero) |
| Cloudflare / капча на сайте | нет |
| Картинки | `8f08a8-ss.akinoncloudcdn.com` (Cloudflare CDN, кэш, без проверки), ~100–250 КБ на фото |
| Запрос с IP прода (204.168.175.164) | список 200 OK за 0,45 с, товар 200 OK за 0,2 с, фото 200 OK |
| Простой User-Agent (`python-requests`) и вообще без него | 200 OK — сайт не фильтрует ботов |
| Несуществующий товар | честный **404** (удобно для ночной сверки) |
| robots.txt | разрешает всё, кроме поиска, сортировок, `?page_size=`, корзины и аккаунта; ИИ-боты явно разрешены |

Вывод: защита отсутствует. Риск, что её включат позже, есть (у Akinon есть свой WAF);
на этот случай план предусматривает «лестницу» транспорта (раздел 4).

### 2.2 Где брать данные

**Список раздела:** `https://www.superstep.com.tr/erkek-ayakkabi/?format=json&page=2`

- `pagination` — номер страницы, всего страниц, всего товаров (48 на страницу);
- `facets` — фильтры с количеством: бренды, пол, подкатегории (`integration_alt_grup`),
  размеры, цвета;
- `products[]` — по каждому товару: название, `price` (цена продажи),
  `retail_price` (цена до скидки), фото (`productimage_set`), все атрибуты
  (включая описание), `extra_data.variants` — цвета этой модели (со ссылками и фото)
  и размеры с признаком «есть/нет».
- Вес страницы в сжатом виде 100–225 КБ.

**Карточка товара:** `https://www.superstep.com.tr/urun/<slug>/<код>/?format=json`

- всё то же, плюс в `variants[].options[].product.stock` — **точный остаток по
  размеру**, SKU и штрихкоды каждого размера;
- `basket_offers` — скидки «в корзине» (например, «SEPETTE %40 İNDİRİM»: 7 999 ₺ на
  витрине → 4 799 ₺ в корзине);
- в сжатом виде ~5 КБ, ответ 0,2–0,5 с.

**Sitemap** (`/sitemap/products-1/`): 19 899 ссылок, но это ссылки на **отдельные
размеры**, а не на модели (уникальных кодов 14 350, есть дубли). Последнее обновление
— 07.10. Для обхода не годится, только для сверки.

**Разделы:** sitemap категорий — 192 раздела (`/erkek-spor-ayakkabi/`,
`/kadin-t-shirt-polo/`, `/cocuk-bot-cizme/` …).

### 2.3 Как устроены товары у Akinon

- **Каждый размер — отдельный «товар»** со своим `pk`, SKU и иногда своей ссылкой.
  Модель объединяет поле `base_code` (например, `KJ3785`). Наш парсер собирает их
  обратно в одну карточку с размерами.
- **Два вида товаров:**
  1. **Собственные** (большинство): атрибуты `integration_*` — цвет
     (`integration_renk`, HEX-цвет), размер (`integration_beden`), модель
     (`integration_model`), сезон, состав (`integration_erp_icerik`), страна
     (`integration_erp_mensei`), совет по размеру («Yarım beden büyük almanı tavsiye
     ederiz» — «берите на полразмера больше»), описание (`integration_kalem_icerik`).
  2. **Маркетплейс** (код начинается с `34-`, поставщик «Fashfed / Eren Perakende» —
     материнская компания SuperStep): атрибуты `mp_size`, `mp_color`, описание
     `mp_description`. Именно у них бывают скидки «в корзине».

  Парсер должен понимать оба набора полей.
- **Цвета** бывают двух видов:
  - внутри одной модели (например, поло Nautica `K35052T` — 4 цвета в одной карточке,
    у каждого цвета свои фото и ссылка);
  - отдельной моделью на каждый цвет (у adidas/Nike цвет = отдельный артикул, в поле
    цвета стоит «-»).
- **Размеры:**
  - обувь — EU, с половинками через запятую: `36`, `36,5`, `42,5`;
  - UK-размер есть в служебном поле (`integration_base_code_format`:
    `KJ3785.-.3,5`) — можно показать справочно;
  - US-размеров в данных нет;
  - одежда — `XS…XXL`, детские — свои значения.
- **Цены** в лирах: `price` — по чему продают, `retail_price` — зачёркнутая.
  НДС уже внутри (`tax_rate` 10/20 %).
- **Лимит:** `max_bag_limit = 2` — сайт не даёт положить больше 2 штук одной позиции.
- **Штрихкод** производителя (`integration_yurt_disi_barkod`, например
  `4068805874772`) — поможет находить одинаковые товары у FLO и SuperStep.

## 3. Как устроено у нас (на что опираемся)

- Каркас парсеров: `backend/apps/scrapers/base/scraper.py` (`BaseScraper`,
  `ScrapedProduct`, запросы с повторами, `_make_offer_request` для живых проверок).
- Регистрация автоматическая: любой класс в `backend/apps/scrapers/parsers/`
  (`registry.py`).
- **Образец по данным — FLO** (`parsers/flo.py`): мультибренд, обувь, группа цветов,
  размеры со штрихкодом, цена продажи + зачёркнутая, `check_offer`, «отпечаток» плитки
  списка для режима «только изменения».
- **Образец по транспорту — Inditex** (`parsers/inditex.py`): чтение JSON API вместо
  HTML.
- **Образец по надёжности и тестам — LCW** (`docs/SCRAPERS_GUIDE.md`, раздел LCW).
- Сохранение: `ScraperIntegrationService` (`scrapers/services.py`) — варианты цветов
  и размеров (`_sync_fashion_variants`), бренды, категории, фото в R2.
- Проверка наличия на карточке: `catalog/services/product_card_source_refresh.py`.
- Проверка в Списке заявки: `SourceOfferVerificationService` → `parser.check_offer()`.
- Ночная сверка: `catalog/services/nightly_stock_check.py` + `docs/STALE_PRODUCTS.md`.
- AI-карточки: правила + Claude, запуск вручную из админки «AI-прогоны».

## 4. Источник данных и обход защиты

### 4.1 Что выбираем

**Прямые запросы к `?format=json`** обычным HTTP-клиентом проекта (`httpx` из
`BaseScraper`), без прокси, с вежливой скоростью:

- списки: 1 запрос в 2–3 секунды;
- карточки: 1 запрос в 1–2 секунды;
- в заголовке — обычный браузерный User-Agent, язык `tr`.

### 4.2 Лестница на случай, если защиту включат

Переходим на следующую ступень, **только если предыдущая перестала работать**:

| Ступень | Инструмент | Цена | Когда |
| --- | --- | --- | --- |
| 1 | `httpx` (уже есть) | 0 $ | сейчас |
| 2 | `curl_cffi` с маскировкой под Chrome (уже есть в проекте для Bershka/Pull&Bear) | 0 $ | если начнут отсекать «не браузеры» по TLS |
| 3 | Резидентный прокси Bright Data (уже подключён) | ~8 $/ГБ | если заблокируют IP сервера; весь каталог ≈ 0,06 ГБ ≈ 0,5 $ за проход |
| 4 | Web Unlocker Bright Data (уже подключён для FLO) | 1,5 $ / 1 000 запросов | если появится капча; только на карточку/Список, как у FLO |

Ступени 3–4 — только с согласия владельца.

### 4.3 Новые инструменты обхода и сравнение с тем, что есть

| Инструмент | Что это | Цена | Нужен ли для SuperStep |
| --- | --- | --- | --- |
| **curl_cffi** | HTTP-клиент, который «выглядит» как настоящий Chrome | бесплатно | уже есть в проекте; в тестах 2026 года проходит Cloudflare не хуже браузеров-невидимок |
| **Patchright** | Playwright без признаков автоматизации | бесплатно | нет — браузер не нужен |
| **Camoufox** | Firefox-невидимка | бесплатно | нет; медленный (~9 с на страницу) |
| **Scrapling** | обёртка: HTTP → браузер → «невидимка» | бесплатно | нет; у нас похожая лестница уже есть |
| **Crawl4AI / Firecrawl** | сбор страниц для ИИ, превращают HTML в текст | бесплатно / платно | нет — у нас уже готовый JSON |
| **Zyte API, ZenRows, ScraperAPI** | платные «разблокировщики», как Web Unlocker | от ~1 $ / 1 000 запросов | нет; если понадобится — Bright Data уже подключён и оплачен по факту |
| **Облачные браузеры** (Browserbase, Bright Data Browser API) | браузер в облаке | платно | нет |

**Вывод:** для SuperStep самый простой и дешёвый способ — прямой JSON без всего
перечисленного. Из новых инструментов полезен только `curl_cffi`, и он у нас уже есть.
Остальные пригодятся сайтам с жёстким Cloudflare (FLO, Zara) — это отдельная тема:
можно попробовать `curl_cffi` вместо Web Unlocker на FLO, чтобы сэкономить лимит.

| Наценка | — | действует обычная цепочка: бренд → категория → общая (`CATEGORY_MARKUP_INHERITANCE.md`) |
| Описание | `integration_kalem_icerik` / `mp_description` (HTML) | в `external_data["source_description"]`; пустое — собрать из характеристик |

## 6. Проверка наличия: карточка и Список заявки

### 6.1 Как устроено сейчас (для всех источников)

- **Открыли карточку на mudaroba.com** → сайт один раз просит сервер проверить
  источник → фоновая задача открывает карточку у поставщика и обновляет цену и
  размеры. Пока проверка идёт, покупатель видит сохранённые данные. Повтор не чаще
  раза в 5 минут.
- **Добавили в Список заявки** → поставщика **не** спрашиваем (берём результат
  проверки карточки, которая была секунды назад).
- **Открыли Список заявки** → одна проверка всех строк (`revalidate`), с кэшем
  2 минуты, не больше 4 одновременных запросов и 60 в минуту на источник.
- Ошибка источника (сайт лёг) ≠ «нет в наличии»: строка остаётся, менеджер уточнит.

### 6.2 Что делаем для SuperStep

1. Метод `check_offer()` в парсере: один запрос
   `<ссылка цвета>?format=json` (~5 КБ), сверяем код модели, берём наличие и цену
   нужного размера.
2. Включаем SuperStep в настройки:
   `PRODUCT_CARD_SOURCE_REFRESH_SOURCES`, `SOURCE_OFFER_VERIFICATION_SOURCES` (и
   запись предложений `SOURCE_OFFER_RECORDING_ENABLED`).
3. **Кэш, чтобы не долбить источник:** SuperStep бесплатный, поэтому окно 24 ч, как
   у FLO, не нужно. Используем общие настройки: результат проверки карточки живёт
   5 минут, в Списке — 2 минуты, ошибка — 15–30 секунд. При 1 000 открытий карточек в
   день это максимум ~1 000 маленьких запросов (≈5 МБ) — для сайта незаметно.
4. **Проверка при добавлении в Список** — как у всех источников (решение владельца):
   само добавление поставщика не вызывает, актуальность обеспечивает проверка
   карточки (секунды назад) и проверка при открытии Списка.

### 6.3 Что видит покупатель

- размер закончился → размер серый, добавить нельзя;
- цена изменилась → новая цена на карточке, в Списке — просьба подтвердить;
- товар снят → «Нет в наличии», товар уходит в кандидаты на снятие (раздел 7).

### 6.4 Точный остаток — не делаем

SuperStep отдаёт точное число штук, но владелец решил, что это не нужно. Наличие
храним как у FLO: «есть/нет» по размеру. Если понадобится позже — достаточно добавить
`superstep` в `EXACT_STOCK_SOURCES`.

## 7. Ночная сверка и снятие исчезнувших товаров

- Добавить `superstep` в `NIGHTLY_STOCK_CHECK_SOURCES` (источник бесплатный, прокси
  не нужен).
- **Дешевле, чем у других:** вместо открытия каждой карточки можно сверять по
  спискам разделов — 330 запросов за ночь дают цены и наличие **всех** товаров.
  Товар, которого нет ни в одном списке, проверяем точечно запросом карточки: 404 —
  значит снят.
  Первая версия — по общему механизму (по карточкам, 6 в минуту, окно 01:00–06:30);
  сверка по спискам — отдельным PR, если общий механизм не успевает за ночь.
  (6 карточек/мин × 330 мин ≈ 2 000 карточек за ночь — на 15 тыс. товаров не хватит,
  поэтому сверка по спискам, скорее всего, понадобится.)
- Признаки «товар снят»: ответ 404 или редирект не на товар (метод
  `is_product_url()` в парсере).
- Снятие — как у всех: исчез один цвет → цвет выключается; исчезла вся модель →
  товар попадает в «Кандидаты на снятие», владелец скрывает после 7 дней, удаляет
  ещё через 14 дней (`docs/STALE_PRODUCTS.md`). Автоматически ничего не удаляется.

### 7.1 Одинаковые товары у FLO и SuperStep: показываем более дорогой

Решение владельца: из двух одинаковых предложений покупатель видит одно — то, что
дороже.

**Как узнаём, что товар тот же.** По штрихкоду производителя (EAN) размеров: у
SuperStep он в `integration_yurt_disi_barkod` (`4068805874772`), у FLO штрихкод
размера уже сохраняется. Совпали штрихкоды хотя бы двух размеров одного цвета — это
одна и та же модель и цвет. Запасной признак, если штрихкодов нет: бренд + артикул
производителя (у adidas `IH9166`, у Nike `FD0884` и т. п.) + цвет. Сравнение по
названию не используем — слишком много ложных совпадений.

**Что сравниваем.** Цену источника в лирах (наценка у обоих одинаковая — по разделу и
бренду, поэтому порядок цен после наценки тот же).

**Что делаем.**
- Более дешёвое предложение **скрываем с сайта** с пометкой «скрыт как дубль товара N»
  (отдельный признак, не путается с «нет в наличии»). Товар и его фото не удаляются.
- Сравнение повторяется после каждого обновления цены (импорт, ночная сверка,
  проверка карточки): если цены поменялись местами — предложения меняются местами.
- Если у более дорогого **нет в наличии ни одного размера**, а у дешёвого есть —
  показываем дешёвый, чтобы товар не пропал с сайта (решение владельца 04.11).
- В админке — список пар «показан / скрыт / почему», чтобы менеджер мог проверить.

Уже есть `DeduplicationService` (`scrapers/services.py`) с кандидатами в дубли на
ручную модерацию, но он выбирает основной товар по источнику и дате, а не по цене, и
сравнивает товары целиком, а не цвета. Поэтому для FLO ↔ SuperStep нужен отдельный
небольшой шаг поверх него (PR 5). Сколько таких пар реально будет — посчитаем на пилоте
(только чтение).

### Режим «только изменения»

- Как у FLO: из плитки списка считаем «отпечаток» (цена, старая цена, размеры
  есть/нет, цвета, число фото). Совпал с прошлым — карточку не открываем.
- Раз в 22–37 дней карточка всё равно перечитывается (общее правило).
- Так повторные прогоны занимают минуты, а не часы.

## 8. Эффективность: сколько запросов и времени

| Действие | Запросов | Трафик | Время |
| --- | --- | --- | --- |
| Весь каталог по спискам (~15 тыс. моделей / 48) | ~330 | ~60 МБ | 15–20 мин |
| Карточки всех моделей (если открывать все) | ~15 000 | ~75 МБ | 5–8 ч при 1 запросе в 1,5 с |
| Повторный прогон «только изменения» | ~330 + изменившиеся | 60–100 МБ | 20–40 мин |
| Фото (до 8 на цвет) | ~100–120 тыс. | ~15–20 ГБ (до сжатия) | растянуть на несколько дней |

Главная нагрузка — фото. Поэтому:

- первый импорт делим на волны по разделам (обувь → одежда → остальное);
- тяжёлое — не в 01:00–06:30 МСК (там ночная сверка);
- до старта проверить место на диске и R2 (`df`), как в памятке о проде.

## 9. Риски

| Риск | Что делаем |
| --- | --- |
| SuperStep включит защиту | лестница из раздела 4.2; парсер ловит 403/429 и капчу и останавливается, не помечая товары «нет в наличии» |
| Akinon поменяет формат JSON | тесты на сохранённых ответах; парсер падает с ошибкой, а не пишет пустые данные (правило §3.11) |
| **Одинаковые товары у FLO и SuperStep** (Nike, adidas, Puma, Skechers …) | показываем более дорогой (раздел 7.1); сопоставление по EAN, не по названию; до PR 5 одинаковые товары могут показываться дважды — поэтому волны импорта брендов, которые есть у FLO, лучше запускать после PR 5 |
| Скидка «в корзине» SuperStep (−40 % и т. п.) | берём цену витрины; скидку в корзине сохраняем в атрибутах для менеджера |
| Размер — отдельный товар у Akinon | собираем по `base_code`, тесты на модель с 14 размерами и «дырами» в ссылках |
| Цвет «-» у adidas/Nike: цвета одной модели — разные артикулы | в первой версии каждый артикул — отдельная карточка (надёжно). Склейку «одна модель — много цветов» по названию модели — только после пилота, если нужно |
| Много фото → место и время | лимит 8 фото, волны, проверка `df` |
| Ограничение 2 шт. на позицию у SuperStep | показывать в Списке заявки предупреждение при количестве > 2 (или просто знать менеджеру) |
| Товар без подходящего раздела (фигурки, шахматы) | не загружаем, показываем в отчёте прогона (раздел 5.1) |
| Ошибочная раскладка (например, «Bot» детский попал во взрослые) | пол берём из данных товара, а не из раздела сайта; пилот 50 включает детские и унисекс товары |
| Ночная сверка не успевает | сверка по спискам (PR 5) |
| Условия сайта | robots.txt разрешает; обходим медленно, без нагрузки |
